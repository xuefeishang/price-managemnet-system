## 场景一：本地开发

### 步骤1：获取代码

```bash
git clone <仓库地址>
cd price-management-system
```

### 步骤2：配置环境变量

```bash
# 复制环境变量模板
cp .env.example .env

# 编辑 .env，填入真实密码
vim .env
```

`.env` 文件内容示例：
```bash
# 数据库配置
DB_HOST=localhost
DB_PORT=3306
DB_NAME=price_management
DB_USERNAME=root
DB_PASSWORD=123abc          # 替换为你的MySQL密码

# Redis配置
REDIS_HOST=10.7.5.175
REDIS_PORT=6379
REDIS_USERNAME=default
REDIS_PASSWORD=123abc       # 替换为你的Redis密码

# JWT配置
JWT_SECRET=price-management-system-secret-key-2024
JWT_EXPIRATION=86400000

# 默认用户密码（重要：生产环境必须修改）
DEFAULT_USER_PASSWORD=admin123

# 外部 API Key 配置（可选）
# 开发环境 application-dev.yml 已提供兜底 key；需要模拟生产密钥时再覆盖
API_KEY_ENCRYPTION_KEY=【可选：Base64编码的32字节随机密钥】
API_KEY_ENCRYPTION_KEY_VERSION=dev

SERVER_PORT=8080
```

PowerShell 生成开发用密钥：

```powershell
$bytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Fill($bytes)
[Convert]::ToBase64String($bytes)
```

开发环境不强制填写 `API_KEY_ENCRYPTION_KEY`；如需覆盖开发兜底 key，请在 IDEA Run Configuration 的 Environment variables 中配置该变量。

### 步骤3：初始化数据库

```bash
mysql -u root -p
```

```sql
CREATE DATABASE IF NOT EXISTS price_management DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
EXIT;
```

```bash
# 执行初始化脚本
mysql -u root -p price_management < backend/src/main/resources/init.sql
```

### 步骤4：启动后端

```bash
cd backend
mvn spring-boot:run
```

### 步骤5：启动前端（另开一个终端）

**H5 前端：**
```bash
cd frontend
npm install
npm run dev
```

**多端前端（可选）：**
```bash
cd frontend-uniapp
npm install
npm run dev:h5          # H5 开发
npm run dev:mp-weixin   # 微信小程序开发
```

### 步骤6：访问系统

- 前端：http://localhost:5173
- 后端：http://localhost:8080
- 普通用户日常查询：登录后进入 **产品管理 → 价格查询**，可按日期/关键字/分类查询并导出当前筛选条件下的价格数据。

### 默认登录账户

| editor | 【敏感-已移除】 | 编辑者 |

## 场景二：更新至GitHub

### 步骤1：确认修改

```bash
git status
git diff
```

### 步骤2：敏感信息检查（自动）

```bash
# 运行审计脚本
./scripts/pre-commit-audit.sh
```

> 如果审计失败（发现敏感信息），脚本会提示你修复后才能提交。

### 步骤3：提交代码

```bash
# 添加文件
git add .

# 提交
git commit -m "你的提交信息"

# 推送到GitHub
git push origin main
```

### 注意事项

- `.env` 文件**不会**被提交（在 .gitignore 中）
- 所有 `.md` 文档中的密码已替换为 `【敏感-已移除】`
- 如需修改密码，编辑 `.env` 文件，不要修改 `.md` 文档

## 场景三：生产部署

### 步骤1：获取代码

```bash
git clone <仓库地址>
cd price-management-system
```

### 步骤2：配置环境变量

```bash
# 复制环境变量模板
cp .env.example .env

# 编辑 .env，填入生产环境密码
vim .env
```

`.env` 文件内容示例（生产环境）：
```bash
# 数据库配置
DB_HOST=localhost
DB_PORT=3306
DB_NAME=price_management
DB_USERNAME=root
DB_PASSWORD=【生产数据库密码】

# Redis配置
REDIS_HOST=10.7.5.175
REDIS_PORT=6379
REDIS_USERNAME=default
REDIS_PASSWORD=【生产Redis密码】

# JWT配置
JWT_SECRET=【生产JWT密钥（使用 openssl rand -base64 32 生成）】
JWT_EXPIRATION=86400000

# 默认用户密码（重要：必须修改为强密码）
DEFAULT_USER_PASSWORD=【强密码】

# 外部 API Key 配置
# 创建 API Key 时必须配置；生产环境必须使用安全随机值
API_KEY_ENCRYPTION_KEY=【Base64编码的32字节随机密钥】
API_KEY_ENCRYPTION_KEY_VERSION=v1

SERVER_PORT=8080
```

### 步骤3：初始化数据库

```bash
mysql -u root -p
```

```sql
CREATE DATABASE IF NOT EXISTS price_management DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
EXIT;
```

```bash
mysql -u root -p price_management < backend/src/main/resources/init.sql
```

### 步骤4：打包后端

```bash
cd backend
mvn clean package -DskipTests
```

产物：`backend/target/price-management-backend-1.0.0.jar`

### 步骤5：部署后端

```bash
# 创建部署目录
mkdir -p /opt/pricemanagement/backend

# 复制jar包
cp backend/target/price-management-backend-1.0.0.jar /opt/pricemanagement/backend/

# 复制环境变量
cp .env /opt/pricemanagement/backend/

# 启动应用
cd /opt/pricemanagement/backend
nohup java -jar price-management-backend-1.0.0.jar > app.log 2>&1 &

# 查看日志
tail -f app.log
```

### 步骤6：部署前端

```bash
# 打包前端
cd frontend
npm install
npm run build
```

```bash
# 安装 Nginx
sudo apt install nginx  # Ubuntu
# 或 sudo yum install nginx  # CentOS

# 创建网站目录
sudo mkdir -p /var/www/pricemanagement

# 复制前端文件
sudo cp -r frontend/dist/* /var/www/pricemanagement/

# 配置 Nginx
sudo vim /etc/nginx/conf.d/pricemanagement.conf
```

Nginx 配置内容：
```nginx
server {
    listen 80;
    server_name your.domain.com;  # 替换为你的域名或IP

    root /var/www/pricemanagement;
    index index.html;

    # 静态资源缓存
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2|ttf|eot)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }

    # 前端路由重定向
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反向代理
    location /api {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        client_max_body_size 10M;
    }
}
```

```bash
# 重启 Nginx
sudo nginx -t
sudo nginx -s reload
```

### 步骤7：验证部署

- 前端：http://your.domain.com
- 后端 API：http://your.domain.com/api
- 健康检查：http://your.domain.com/api/auth/login

## 场景四：Docker Compose 生产部署

### 适用场景

- 已有项目在生产环境运行，需要更新代码重新部署
- 使用 Docker 容器化部署前后端应用

### 前提条件

- 生产服务器已安装 Docker 和 Docker Compose
- 项目目录位于 `/opt/price-management-system`
- 环境变量配置文件 `.env` 已存在
- `.env` 中已配置 `API_KEY_ENCRYPTION_KEY`，否则后台无法创建 API Key
- Docker Compose 默认以 `SPRING_PROFILES_ACTIVE=prod` 启动后端，生产环境不会加载开发兜底 key
- 外部 API 上线前按 [外部API生产部署检查清单.md](外部API生产部署检查清单.md) 完成核对

### 步骤1：本地代码提交并推送

```bash
# 查看当前修改状态
git status --short

# 添加所有修改
git add .

# 提交（附带规范的提交信息）
git commit -m "$(cat <<'EOF'
feat: 功能描述

主要变更：
- 变更点1
- 变更点2

Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>
EOF
)"

# 推送到远程仓库
git push origin master
```

> **注意**：如果 GitHub 连接超时，可多次重试或检查网络代理配置。

### 步骤2：生产环境拉取最新代码

```bash
# SSH 连接生产服务器，强制同步远程代码
ssh root@10.7.5.175 "cd /opt/price-management-system && git checkout -- . && git clean -fd && git pull origin master"

# 查看拉取结果
ssh root@10.7.5.175 "cd /opt/price-management-system && git log --oneline -3"
```

**说明**：
- `git checkout -- .` 丢弃本地未提交修改
- `git clean -fd` 删除未跟踪的文件和目录
- 这样可避免拉取时的冲突问题

### 步骤3：停止并重建 Docker 容器

```bash
# 停止并删除现有容器
ssh root@10.7.5.175 "cd /opt/price-management-system && docker compose down"

# 无缓存重新构建镜像（确保使用最新代码）
ssh root@10.7.5.175 "cd /opt/price-management-system && docker compose build --no-cache"

# 启动容器
ssh root@10.7.5.175 "cd /opt/price-management-system && docker compose up -d"
```

**说明**：
- `--no-cache` 确保不使用旧的缓存层，完全重新构建
- `-d` 后台运行模式

### 步骤4：等待并验证健康检查

```bash
# 等待后端启动（约60-90秒）
ssh root@10.7.5.175 "sleep 90 && docker ps --format 'table {{.Names}}\t{{.Status}}' | grep price-management"

# 验证服务可用性
ssh root@10.7.5.175 "curl -s http://localhost:80/api/auth/captcha | head -c 200"
```

**预期结果**：
- `price-management-backend` 状态为 `(healthy)`
- `price-management-frontend` 状态为 `Up`
- API 返回 JSON 格式的验证码数据

### 步骤5：查看日志排查问题

如果服务异常，查看容器日志：

```bash
# 后端日志
ssh root@10.7.5.175 "docker logs price-management-backend --tail=100"

# 前端日志
ssh root@10.7.5.175 "docker logs price-management-frontend --tail=50"

# 筛选错误日志
ssh root@10.7.5.175 "docker logs price-management-backend 2>&1 | grep -i 'error\|exception' | tail -30"
```

### 一键部署命令

将以上步骤合并为一条命令：

```bash
# 本地提交
git add . && git commit -m "feat: 功能描述" && git push origin master

# 生产部署（等待GitHub同步后执行）
ssh root@10.7.5.175 "cd /opt/price-management-system && git checkout -- . && git clean -fd && git pull origin master && docker compose down && docker compose build --no-cache && docker compose up -d"
```

### 验证清单

| 检查项 | 命令 | 预期结果 |
|--------|------|----------|
| 容器状态 | `docker ps` | backend (healthy), frontend Up |
| 前端首页 | `curl localhost:80/` | HTTP 200 |
| API 接口 | `curl localhost:80/api/auth/captcha` | JSON 响应 |
| 后端直接访问 | `curl localhost:8080/api/products` | JSON 响应（可能 401） |

## 常见问题

### Q1：忘了运行审计脚本就提交了怎么办？

```bash
# 撤回上次提交
git reset --soft HEAD~1

# 运行审计
./scripts/pre-commit-audit.sh

# 重新提交
git commit -m "重新提交"
git push
```

### Q2：忘记了数据库密码怎么办？

查看服务器上的 `.env` 文件（没有被上传到 GitHub）。

### Q3：如何更新生产环境密码？

在生产服务器上编辑 `/opt/pricemanagement/backend/.env`，然后重启应用：

```bash
cd /opt/pricemanagement/backend
pkill -f price-management-backend
nohup java -jar price-management-backend-1.0.0.jar > app.log 2>&1 &
```

### Q4：GitHub 推送被拒绝？

```bash
# 检查是否已设置 SSH key
cat ~/.ssh/id_rsa.pub

# 如果没有，生成一个
ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

# 将公钥复制到 GitHub Settings -> SSH Keys
```

### Q5：服务器上 Redis 连接失败？

检查 `.env` 中的 Redis 配置：
```bash
REDIS_HOST=10.7.5.175
REDIS_PORT=6379
REDIS_PASSWORD=123abc
```

确认服务器能访问 Redis：
```bash
telnet 10.7.5.175 6379
```

### Q6：GitHub 推送超时？

```bash
# 多次重试
git push origin master

# 或检查代理配置
git config --global http.proxy
```

### Q7：Git 拉取冲突？

```bash
# 强制同步远程版本
ssh root@10.7.5.175 "cd /opt/price-management-system && git fetch origin && git reset --hard origin/master && git clean -fd"
```

### Q8：Docker 容器名称冲突？

```bash
# 强制删除旧容器
ssh root@10.7.5.175 "docker rm -f price-management-frontend price-management-backend"
```

### Q9：前端 502 Bad Gateway？

检查 nginx 代理配置：

```nginx
# nginx.conf - 使用 host.docker.internal 访问宿主机端口
location ^~ /api/ {
    proxy_pass http://host.docker.internal:8080/api/;
    # ...
}
```

**原因**：后端使用 `network_mode: host`，前端使用 bridge 网络，两者网络隔离。前端容器内的 `127.0.0.1` 指向容器自身而非宿主机。

### Q10：Docker 健康检查失败？

当前项目使用 TCP 端口检查：

```yaml
# docker-compose.yml 中的健康检查配置
healthcheck:
  test: ["CMD", "nc", "-z", "localhost", "8080"]
  interval: 30s
  timeout: 10s
  retries: 3
  start_period: 60s
```

如需 HTTP 检查，需添加 `spring-boot-starter-actuator` 依赖。

### Q11：浏览器最小化后窗口立即恢复？

本系统前端已在路由层兼容部分 Edge/Chrome 环境的最小化恢复问题。若升级依赖或重构前端后问题复现，优先检查：

- `frontend/src/router/index.ts` 是否仍通过 `createAppHistory()` 创建 history，而不是直接调用 `createWebHistory()`。
- 首页 ECharts 是否仍通过 `useSafeChartAutoresize()` 绑定 `:autoresize="chartAutoresize"`。
- `useLayout()` 是否仍在页面隐藏、窗口外框极小或最小化负坐标状态下忽略 resize。

验证方式：打开 `http://localhost:5173/home`，点击浏览器最小化按钮，窗口应保持最小化，不应立即恢复。

### Q12：修改 .env 后容器内环境变量没更新？

**原因：** `docker compose restart` 只重启容器，不会重新读取 `.env` 文件。

**解决方案：** 使用 `down + up` 重建容器：

```bash
cd /opt/price-management-system
docker compose down && docker compose up -d
```

**验证环境变量是否生效：**

```bash
docker exec price-management-backend env | grep API_KEY
```

## Docker 部署知识

### 镜像 vs 容器 vs 源代码

| 概念 | 类比 | 存储位置 | 可变性 |
|------|------|----------|--------|
| **源代码** | 原材料 | `/opt/price-management-system/` | 开发时修改 |
| **镜像** | 安装包 | Docker 内部存储 `/var/lib/docker/` | 构建后只读 |
| **容器** | 运行中的程序 | 内存中 | 可注入配置 |

### 构建和部署流程

```
源代码 (/opt/price-management-system/)
    │
    │  docker compose build
    │  （Dockerfile 指令：编译 Java/Vue → 打包成 JAR/静态文件）
    ↓
镜像 (image)
    │  存储在 Docker 内部，不含源码
    │  只包含编译产物 + 运行时
    │
    │  docker compose up -d
    │  （读取 .env + docker-compose.yml → 注入环境变量）
    ↓
容器 (container)
    │  运行中的实例
    │  镜像 + 环境变量 + 网络配置
    ↓
访问服务 (http://10.7.5.175)
```

### 环境变量传递机制

环境变量**不在镜像内**，在容器启动时注入：

```yaml
# docker-compose.yml
services:
  backend:
    environment:
      - API_KEY_ENABLED=${API_KEY_ENABLED:-false}  # 从 .env 读取
      - DB_PASSWORD=${DB_PASSWORD}                  # 从 .env 读取
```

**关键点：**

- `.env` 文件：存储环境变量值
- `docker-compose.yml`：定义如何将变量传递给容器
- `docker compose up`：创建容器时注入环境变量

### 各命令的作用

| 命令 | 作用 | 是否读取 .env | 是否需要源代码 |
|------|------|---------------|----------------|
| `docker compose build` | 源码编译成镜像 | 否 | **需要** |
| `docker compose up -d` | 创建并启动容器 | **是** | 否（只需镜像） |
| `docker compose restart` | 重启已有容器 | **否** | 否 |
| `docker compose down` | 停止并删除容器 | 否 | 否 |

### 什么时候需要重新 build

| 修改内容 | 需要的操作 |
|----------|-----------|
| Java/Vue 源代码 | `docker compose build --no-cache && docker compose up -d` |
| `.env` 环境变量 | `docker compose down && docker compose up -d` |
| `docker-compose.yml` | `docker compose down && docker compose up -d` |
| `nginx.conf` | `docker compose build --no-cache frontend && docker compose up -d` |

### 常用 Docker 命令

```bash
# 查看本地镜像
docker images

# 查看运行中的容器
docker ps

# 查看容器日志
docker logs price-management-backend --tail=100

# 进入容器内部
docker exec -it price-management-backend sh

# 查看容器环境变量
docker exec price-management-backend env

# 查看容器详细信息（含环境变量）
docker inspect price-management-backend | grep -A20 Env

# 强制删除容器
docker rm -f price-management-backend price-management-frontend

# 删除镜像
docker rmi price-management-backend:latest

# 清理无用镜像和缓存
docker system prune -a
```
