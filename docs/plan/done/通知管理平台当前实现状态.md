# 通知管理平台当前实现状态

更新时间：2026-06-11

## 文档职责

本文是通知管理平台“当前已经实现什么、还缺什么、审计发现什么风险”的唯一事实源。状态必须以当前代码、数据库迁移和最近一次验证结果为准。

- 目标设计与历史决策：见 [notification-management-platform-feature.md](notification-management-platform-feature.md)
- 尚未闭环工作的实施计划：见 [notification-management-platform-closure-feature.md](notification-management-platform-closure-feature.md)

状态口径：

- `[x]`：代码已实现，并存在本地自动化验证或明确代码证据。
- `[~]`：主体代码已实现，但仍缺生产等价环境、真实外部平台验证或规模验证。
- `[ ]`：尚未实现。

本次审计口径：基于 2026-06-10 当前代码、`init.sql`、Flyway 迁移、前端 API 调用和测试文件进行核验；真实微信平台、真实 MySQL 压测和生产环境权限/日志不在本地静态审计中自动视为完成。

## 当前结论

通知管理平台的站内消息、Outbox、管理后台、系统公告、微信小程序订阅消息代码链路和 PC 运维主体已经实现。四期“通讯管理/小程序订阅运维”不能仅凭页面按钮和本地构建宣称 9.5+ 完整闭环，剩余门槛集中在：

1. 微信真实模板、真实授权、真实投递、正式公告触达和点击跳转仍缺联调证据。
2. 真实 MySQL 的索引命中、分页性能、Outbox 并发领取和大数据量验证仍缺记录。
3. 生产角色授权、按钮显隐、后端拒绝行为和历史敏感日志仍缺上线环境复核记录。
4. “跟进任务”尚未实现，当前只有用户级 `followUpRequired` 跟进标记。
5. 外部验证完成前，`WX-*`、`DB-*`、`OPS-*` 仍是四期闭环门槛；本地已补齐批量授权引导分页化、投递审计分页、模板维护校验和证据归档模板。
6. 小程序渠道的模板删除/清空、微信消息 `messageId` 精准跳转、默认配置解耦、永久错误分类、授权次数条件预占、授权请求分批和 PC “小程序模板”独立运维页签已完成主体代码；模板 ACTIVE 唯一性、草稿创建模式、旧渠道配置迁移、影响评估性能和模板校验 API 语义已完成代码收口，仍需真实 MySQL 升级演练和真实微信投递证据。
