# 小程序角色化导航与轻量移动功能升级方案

> 实施状态：已完成第一阶段代码实现。小程序已新增“历史”页，底部导航按角色展示；VIEWER 为“首页 / 历史 / 我的”，ADMIN/EDITOR 为“首页 / 历史 / 录入 / 我的”。移动端完整运维入口已收敛，产品、分类、产地、客户、审批、字典、用户等完整维护回到 PC 端。

## Context

当前 `frontend-uniapp` 已具备小程序/H5/APP 多端基础能力，页面包括：

- `pages/home/index`：价格概览、日期选择、分类筛选、重点指标、产品列表、风险预警。
- `pages/products/list`：产品入口页，当前承担统计卡片、快捷入口、最近产品等“运维集合页”语义。
- `pages/price-maintenance/index`：价格维护。
- `pages/profile/index`：个人中心，并承载价格维护、分类、产地、客户、审批等入口。
- `pages-sub/basic/categories|origins|customers`：基础运维分包页面。

问题是当前小程序的底部导航仍偏 PC 后台菜单压缩版：

- 普通员工日常只需要看行情、查历史、进入我的，但底部仍有“产品”入口，信息架构偏后台。
- 管理员和编辑者在移动端只适合做少量应急操作，例如补录价格、查看待办；产品、分类、客户、产地等完整基础运维仍应回到 PC 端完成。
- `Products` 页既像产品列表，又像运维首页，语义不稳定。
- PC 端已经形成成熟能力：`Home`、`PriceQuery`、`PriceMaintenance`、`Products`、`Categories`、`Origins`、`Customers`。小程序应以 PC 端业务能力为基础做移动任务化，而不是复制 PC 左侧菜单。

本方案目标是将小程序升级为 **普通员工三入口 + 管理员轻量操作入口**：

```text
普通员工： 首页 / 历史 / 我的
管理员/编辑者： 首页 / 历史 / 录入 / 我的
```

其中“历史”对应 PC 端价格查询/历史价格能力，“录入”仅对应 PC 端价格维护中的移动端高频子集。产品、分类、客户、产地、审批配置、字典、用户等运维仍以 PC 端为唯一主入口。

## Goals

1. 普通员工底部 Tab 只展示：首页、历史、我的。
2. 管理员和编辑者额外展示“录入”Tab，仅承载移动端适合完成的价格录入/补录任务。
3. 首页继续以 PC 首页为业务基础，保留日期行情、重点指标、产品列表、风险预警，但减少管理入口干扰。
4. 历史页以 PC `PriceQuery` 为基础，提供只读价格历史查询、产品搜索、分类筛选、趋势查看。
5. 录入页以 PC `PriceMaintenance` 为基础，保留日期选择、搜索/分类筛选、价格录入、保存变更和必要对照信息。
6. 我的页聚焦个人资料、账号状态、退出登录和低频设置，不再承担主要运维导航。
7. 权限控制同时体现在 Tab、页面入口、页面访问拦截和后端接口权限四层，避免仅靠隐藏按钮。

## Non-Goals

- 本方案不重写后端接口。
- 本方案不要求小程序复制 PC 后台管理能力，例如产品、分类、客户、产地、用户管理、菜单配置、日志管理、样式设置。
- 本方案不新增数据库表。
- 本方案不在普通员工端暴露任何新增/编辑/删除入口。
- 本方案不在小程序端提供产品、分类、客户、产地的完整 CRUD；这些工作回到 PC 端完成。
- 本方案不改变 PC 端页面结构，仅以 PC 端能力作为小程序信息架构和交互依据。

## 角色与信息架构

### 角色分层

| 角色 | 小程序定位 | 底部 Tab | 关键能力 |
|------|------------|----------|----------|
| VIEWER / 普通员工 | 行情查看与历史追溯 | 首页、历史、我的 | 看当日/历史价格、搜索产品、查看趋势、个人中心 |
| EDITOR | 日常价格录入与补录 | 首页、历史、录入、我的 | 普通员工能力 + 价格录入 |
| ADMIN | 移动端应急录入与检查 | 首页、历史、录入、我的 | EDITOR 能力 + 后续可选待办提醒 |

> 若后端已返回动态权限集合，应优先使用权限码判断；短期可兼容 `role === ADMIN/EDITOR` 的 `canEdit`。

### 推荐底部导航

普通员工：

```text
首页    历史    我的
```

管理员/编辑者：

```text
首页    历史    录入    我的
```

### 页面职责

| 页面 | 普通员工 | 管理员/编辑者 | PC 对应能力 |
|------|----------|---------------|-------------|
| 首页 | 默认行情驾驶舱 | 默认行情驾驶舱，可展示“今日待录入”摘要 | `Home.vue` |
| 历史 | 价格历史查询、趋势查看 | 同普通员工，可作为录入前查询辅助 | `PriceQuery.vue` |
| 录入 | 不可访问 | 价格录入、补录、今日录入状态 | `PriceMaintenance.vue` |
| 我的 | 个人信息、退出登录 | 个人信息、退出登录、低频设置 | `Profile.vue` |

### PC 与移动端边界

本方案的核心取舍是：**PC 负责完整运维，小程序负责查询和轻量录入**。

| 能力 | PC 端 | 小程序端 |
|------|-------|----------|
| 行情首页 | 完整驾驶舱、表格、配置联动 | 移动行情概览 |
| 历史价格 | 完整查询、筛选、趋势、导出 | 只读查询、趋势查看 |
| 价格录入 | 完整价格维护工作台 | 轻量录入/补录 |
| 产品维护 | 新增、编辑、删除、排序、导入导出 | 只读查看或详情跳转，不做维护 |
| 分类/产地/客户 | 完整 CRUD | 不作为主功能；需要维护时提示去 PC |
| 字典/用户/菜单/日志/样式 | 完整后台管理 | 不提供 |
| 审批配置 | 完整配置与处理 | 暂不提供；后续最多提供待办提醒 |

## 推荐页面设计

### 1. 首页

保持当前 `pages/home/index` 的行情查看定位，弱化管理入口：

- 删除或隐藏普通员工不可见的悬浮“价格维护”入口。
- 管理员/编辑者首页可保留轻量提示，例如“今日待录入 N 个产品”，点击进入录入页。
- 日期默认沿用 PC 首页逻辑，优先展示昨日行情，支持切换日期。
- 产品列表保持只读，点击进入产品详情或历史页产品视角。
- 首页不再承担“产品管理”入口，避免普通员工误解为可维护产品。

### 2. 历史页

新增或改造一个主包页面，例如：

```text
frontend-uniapp/src/pages/history/index.vue
```

历史页是普通员工的第二个核心入口，应以 PC `PriceQuery` 的只读能力为基础：

- 顶部：日期选择 + 搜索框。
- 筛选：分类横向标签，必要时增加产品状态筛选但默认只看启用产品。
- 主体：产品价格列表，字段建议为产品名称、规格/产地、当日售价、昨日售价、较昨日。
- 趋势：点击产品后进入详情页或在当前页展开趋势卡，支持 7日/30日/90日。
- 空状态：无价格时显示“该日期暂无报价”，不能让用户误以为无产品。

历史页不提供：

- 新增价格。
- 编辑价格。
- 产品编辑。
- 导出按钮，除非后续确认小程序端有真实导出使用场景。

### 3. 录入页

将当前 `pages/price-maintenance/index` 升级为移动端唯一主要操作页。建议 Tab 路径为：

```text
frontend-uniapp/src/pages/price-maintenance/index.vue
```

不再新增“运维工作台”作为完整后台入口，也不建议把 `pages/products/list` 继续作为底部 Tab。产品列表可以作为历史页/首页的详情跳转目标，或作为管理员从 PC 端之外的只读查看补充，但不作为移动端主导航。

录入页只服务一个任务：按日期快速录入或补录产品价格。

```text
日期选择
搜索 / 分类筛选
产品价格卡片列表
保存变更
```

录入页首屏建议：

| 区域 | 内容 | 说明 |
|------|------|------|
| 日期与保存栏 | 当前日期、前后一天、保存按钮 | 对齐 PC 价格维护的日常录入场景 |
| 录入进度 | 已录入/总产品、缺失报价数 | 让移动端知道是否还需要补录 |
| 筛选区 | 搜索产品、分类筛选 | 产品多时避免长列表低效 |
| 价格卡片 | 产品名、规格/产地、当日售价输入、预算价、昨日价、较昨日、月均价 | 保留必要上下文，避免误录 |

价格录入需要按 PC 价格维护页补齐体验：

- 默认日期与首页业务节奏一致，建议默认昨日。
- 顶部固定保存按钮。
- 支持搜索产品和分类筛选，避免产品多时长列表难用。
- 只提交发生变化的产品价格。
- 展示预算价、昨日价、较昨日、月均价，和 PC 口径一致。
- 不提供新增产品、编辑产品、删除产品、分类维护、客户维护、产地维护。
- 如遇需要新增产品或维护基础资料，页面提示“请前往 PC 端运维”。

### 4. 我的页

`pages/profile/index` 回归个人中心，不再做主要运维菜单：

- 用户卡片：昵称、角色、账号状态。
- 我的功能：个人资料、账号安全、退出登录。
- 普通员工不显示任何运维入口。
- 管理员可以保留“进入价格录入”快捷跳转，但不是运维集合入口。
- 角色显示应从字典或后端角色名称获取，避免硬编码“管理员/编辑者/查看者”长期存在。

## 路由与 TabBar 改造

### pages.json 建议

主包页面建议调整为：

```json
{
  "pages": [
    "pages/login/index",
    "pages/home/index",
    "pages/history/index",
    "pages/price-maintenance/index",
    "pages/profile/index",
    "pages/products/detail",
    "pages/products/edit"
  ]
}
```

`tabBar.list` 静态配置受小程序限制，不能完全动态增减时，建议使用自定义 tabbar：

- `custom-tab-bar/index.vue` 根据 `userStore.canEdit` 生成 Tab。
- VIEWER：Home / History / Profile。
- ADMIN/EDITOR：Home / History / PriceMaintenance / Profile。
- 若使用原生 tabBar，需保留 4 项但普通员工点击“录入”时提示无权限并跳转首页；体验不如自定义 tabbar。

### 自定义 TabBar 数据源

建议抽出统一配置：

```ts
const baseTabs = [
  { key: 'home', pagePath: '/pages/home/index', text: '首页' },
  { key: 'history', pagePath: '/pages/history/index', text: '历史' },
  { key: 'profile', pagePath: '/pages/profile/index', text: '我的' }
]

const entryTab = { key: 'entry', pagePath: '/pages/price-maintenance/index', text: '录入' }
```

并按角色插入：

```text
普通员工：home, history, profile
管理员/编辑者：home, history, entry, profile
```

## 权限控制

### 前端控制

| 层级 | 要求 |
|------|------|
| Tab 展示 | 普通员工不显示录入 Tab |
| 页面进入 | `price-maintenance`、编辑页进入前检查权限 |
| 按钮展示 | 新增、编辑、删除、保存仅对 `canEdit` 或具体权限码可见 |
| 异常处理 | 403 或业务无权限时提示“无权访问该功能”并返回首页或我的 |

### 后端控制

小程序不能只依赖前端隐藏入口。后端接口仍需保持当前权限校验：

- 价格写入接口仅 ADMIN/EDITOR 或对应权限可访问。
- 产品、分类、产地、客户等完整运维接口仍由 PC 端使用，小程序端不新增这些入口；后端权限仍必须保留。
- 普通员工历史查询只使用只读接口。

## API 对齐

当前小程序已有 API 模块：

| 文件 | 现有能力 | 升级用途 |
|------|----------|----------|
| `api/products.ts` | 产品列表、详情、价格走势、价格维护 | 首页、历史、价格录入 |
| `api/categories.ts` | 分类 CRUD | 首页/历史/录入的分类筛选；CRUD 不作为移动端主功能 |
| `api/origins.ts` | 产地 CRUD | 产品展示辅助；CRUD 不作为移动端主功能 |
| `api/customers.ts` | 客户 CRUD | 暂不作为移动端主功能 |
| `api/home.ts` | 首页摘要、预警、趋势 | 首页 |
| `api/auth.ts` | 登录、刷新、个人资料 | 角色与权限判断 |

建议补齐：

- 小程序端字典服务：复用 PC `useDict` 的理念，避免状态、角色、操作类型中文硬编码。
- 历史页 API 封装：围绕 `getPricesByDateWithStats`、`getProductPriceTrend` 建立更清晰的 `history.ts` 或在 `products.ts` 中统一命名。
- 权限工具：从 `useUserStore` 的 `isAdmin/canEdit` 逐步升级为 `hasPermission(permissionCode)`。

| 场景 | 账号 | 预期 |
|------|------|------|
| 登录普通员工 | VIEWER | 底部只显示：首页、历史、我的 |
| 普通员工访问录入 URL | VIEWER | 提示无权限并返回首页或我的 |

| 登录管理员 | ADMIN | 可进入小程序价格录入入口，但产品/分类/客户等完整运维仍回到 PC |

| 页面 | 验收点 |

## 风险与取舍

| 风险 | 影响 | 缓解 |
|------|------|------|
| 小程序原生 tabBar 不支持按角色动态增减 | 普通员工仍可能看到录入 Tab | 使用自定义 tabbar，或保留原生 Tab 但进入时拦截 |
| 移动端运维过度膨胀 | 移动端变成 PC 菜单复制 | 明确不做完整运维，只保留价格录入 |
| 普通员工误操作 | 数据被误改 | 前端隐藏 + 页面守卫 + 后端权限三重保护 |
| 历史页和首页重复 | 用户分不清入口 | 首页看“当前/选定日期概览”，历史做“查询与追溯” |
| 小程序包体增加 | 首屏变慢 | 保持录入页轻量，产品/分类/客户等完整运维不进入移动端主链路 |

## 推荐优先级

| 优先级 | 内容 | 价值 |
|--------|------|------|
| P0 | 角色化 Tab、历史页、录入入口重组 | 解决信息架构和权限边界 |
| P1 | 价格录入页搜索/分类筛选、我的页收敛 | 提升管理员日常补录效率 |
| P2 | 首页和历史页信息展示对齐 PC 口径 | 完整普通员工移动查询闭环 |
| P3 | 小程序端字典服务和动态权限码工具 | 消除硬编码并提升长期可维护性 |
