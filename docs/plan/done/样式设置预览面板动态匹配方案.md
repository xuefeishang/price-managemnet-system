# 样式设置交互式预览与统一保存方案

> 状态：已合并到 [style-settings-multi-platform-upgrade-improvement-feature.md](style-settings-multi-platform-upgrade-improvement-feature.md)。
>
> 后续开发以 `style-settings-multi-platform-upgrade-improvement-feature.md` 为唯一执行方案；本文仅作为统一保存、草稿预览、版本快照治理的历史来源保留。

## Context

当前问题：
- 每次配置变更立即保存并创建版本快照
- Logo base64 数据量大，导致快照 JSON 过长
- 频繁操作产生大量版本记录

用户需求：
- 配置变更时仅更新预览区（响应式）
- 点击"保存"按钮后才持久化配置 + 创建版本快照
- 避免频繁快照，版本记录有意义

## 实现方案

### 核心设计

**三阶段状态模型：**
1. **serverConfig** — 服务端已保存的配置（回滚基准）
2. **draftConfig** — 当前编辑中的配置（预览数据源）
3. **appliedConfig** — 已应用到 CSS 变量的配置（全局生效）

**交互流程：**
```
配置变更 → updateDraft() → 更新 draftConfig → 预览区响应
点击保存 → saveConfig() → 持久化 + 创建快照 → appliedConfig 更新
```

### 前端改造

#### 1. useStyleSettingsWorkbench.ts 改造

**新增方法：**
```typescript
// 仅更新预览（不保存）
const updateDraft = (patch: Partial<StyleConfig>) => {
  if (!draftConfig.value) return
  Object.assign(draftConfig.value, patch)
  saveStatus.value = 'dirty' // 标记为未保存
}

// 保存配置（持久化 + 快照）
const saveConfig = async () => {
  if (!draftConfig.value) return
  saveStatus.value = 'saving'
  try {
    await updateStyleConfig(draftConfig.value)
    serverConfig.value = clone(draftConfig.value)
    appliedConfig.value = clone(draftConfig.value)
    applyThemeToCSS(draftConfig.value) // 全局生效
    saveStatus.value = 'saved'
    lastSavedAt.value = new Date().toISOString()
  } catch (error) {
    saveStatus.value = 'failed'
    lastError.value = '保存失败'
  }
}

// 放弃修改（恢复到服务端配置）
const discardChanges = () => {
  if (!serverConfig.value) return
  draftConfig.value = clone(serverConfig.value)
  saveStatus.value = 'idle'
}
```

**废弃方法：**
- `applyAndPersist` — 拆分为 `updateDraft` + `saveConfig`

**保留方法（需改造）：**
- `applyColorScheme` → 改为仅更新 draftConfig
- `applyLayoutStyle` → 改为仅更新 draftConfig
- `applyFontPreset` → 改为仅更新 draftConfig

#### 2. StyleSettingsWorkbench.vue 改造

**新增保存按钮区域：**
```vue
<div class="workbench-header">
  <div class="save-actions">
    <span v-if="saveStatus === 'dirty'" class="unsaved-hint">有未保存的更改</span>
    <button class="btn-discard" @click="discardChanges" :disabled="saveStatus !== 'dirty'">放弃修改</button>
    <button class="btn-save" @click="saveConfig" :disabled="saveStatus !== 'dirty'">
      {{ saveStatus === 'saving' ? '保存中...' : '保存配置' }}
    </button>
  </div>
</div>
```

**保存状态提示：**
- `idle` — 无变化
- `dirty` — 有未保存更改（显示提示）
- `saving` — 保存中
- `saved` — 已保存
- `failed` — 保存失败

#### 3. 各配置面板改造

**BrandSettingsPanel.vue：**
- `updateSystemName` → 调用 `updateDraft({ systemName: value })`
- `updateLogoSizeLogin` → 调用 `updateDraft({ logoSizeLogin: size })`
- `updateSubtitleFont` → 调用 `updateDraft({ subtitleFont: font })`
- Logo 上传后 → 调用 `loadWorkbenchConfig(true)` 刷新数据

**ColorSchemePanel.vue：**
- 色彩方案选择 → 调用 `updateDraft({ activeColorScheme: key })`
- 颜色输入变更 → 调用 `updateDraft({ priceRiseColor: value })`

**LayoutStylePanel.vue：**
- 布局方案选择 → 调用 `updateDraft({ activeLayoutStyle: key })`

**FontSizePanel.vue：**
- 字号预设选择 → 调用 `updateDraft({ fontSizePreset: key })`
- 自定义字号 → 调用 `updateDraft({ fontSizeBase: value })`

### 后端改造

#### 1. StyleConfigService.java 改造

**版本快照排除 Logo 字段：**
```java
// 创建快照时排除大字段
private String createConfigSnapshot(StyleConfigDTO config) {
    StyleConfigDTO snapshot = new StyleConfigDTO();
    BeanUtils.copyProperties(config, snapshot);
    // 排除 Logo base64 字段
    snapshot.setLogoUrl(null);
    snapshot.setLogoUrlLogin(null);
    snapshot.setLogoUrlNav(null);
    return objectMapper.writeValueAsString(snapshot);
}
```

**说明：** Logo 数据单独存储在 `sys_style_config` 表，版本快照仅记录配置项，不包含图片数据。

#### 2. StyleVersionService.java 改造

**快照 JSON 结构优化：**
- 仅包含配置项（颜色、字体、布局等）
- 不包含 Logo base64 数据
- 添加 `excludedFields` 字段说明被排除的字段

### 预览区响应式更新

**PreviewPanel.vue：**
- 绑定 `draftConfig` 而非 `appliedConfig`
- 配置变更时预览立即响应
- 不影响全局 CSS 变量

**预览数据流：**
```
draftConfig → PreviewPanel → 实时预览
appliedConfig → 全局 CSS 变量 → 系统生效
```
