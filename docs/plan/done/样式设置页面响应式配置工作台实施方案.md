# 样式设置页面响应式配置工作台实施方案

**创建日期：2026-05-20**  
**适用范围：** `frontend/src/views/StyleSettings.vue`、`frontend/src/components/style-settings/*`、`frontend/src/composables/useTheme.ts`、`frontend/src/api/style.ts`、`frontend/src/constants/dictCategoryMeta.ts`、`/api/style/*`、`home_layout`、`home_widget`、`category_visual_config`  
**目标：** 将 Style Settings 从“配置长表单”升级为“响应式配置工作台”：功能分区清晰、修改后可即时预览、必须点击保存后才正式生效、再次进入页面能准确回显当前已保存状态，并完整承接 Dict Management 中受保护的 UI/视觉配置。

## 一、背景与问题判断

当前 Style Settings 页面已经具备部分能力：

- 系统名称、Logo、Logo 尺寸
- 预设主题
- 色彩方案
- 布局方案
- 字体和字号预设
- 自定义颜色
- 右侧预览
- 历史版本与回滚

但当前体验存在明显问题：

| 问题 | 当前表现 | 影响 |
|------|----------|------|
| 信息架构混乱 | 系统名称、主题、色彩、布局、字体、Logo、版本混在长页面中 | 管理员不知道该先改什么，也难定位配置 |
| 操作反馈割裂 | 部分选择会立即调接口，部分只改 `editingConfig`，部分要保存后才生效 | 用户感知不一致 |
| 当前状态回显不准 | 回到 Style Settings 后，选中项可能显示默认值，而不是系统当前生效值 | 用户不信任配置页 |
| 预览与真实系统割裂 | 页面有预览，但真实系统变化和预览变化不完全同源 | 预览不能代表最终效果 |
| 受保护内容未完整承接 | `dictCategoryMeta.ts` 保护了 `home_layout`、`home_widget`、`category_visual_config`，但 Style Settings 未完整提供管理入口 | Dict Management 不能编辑，Style Settings 又不全，形成配置断点 |
| 页面视觉不够专业 | 大量卡片堆叠、层级不清、操作按钮分散 | 后台配置中心不够沉稳高效 |

### 1.1 必须遵循的项目设计要求

根据 `docs/dev/项目设计文档.md`，本方案必须遵循：

| 要求来源 | 要求 | 本方案响应 |
|----------|------|------------|
| 禁止硬编码原则 | 编码显示名称从字典服务动态获取 | Style Settings 不硬编码业务字典标签 |
| 全局样式管理 | 支持主题、颜色、字体、Logo、实时预览 | 保留并重组现有功能 |
| 样式管理 API | 使用 `/api/style/config`、`/api/style/themes`、`/api/style/logo` 等 | 保持 `/api/style` 专业入口 |
| CSS 变量动态化 | 样式通过 CSS 变量实时生效 | 选择即调用 `applyThemeToCSS()` |
| UnoCSS 架构 | UnoCSS 与 CSS 变量结合，语义化 shortcuts | 新页面使用 UnoCSS 管结构，scoped CSS 管复杂状态 |
| 分类视觉系统 | `category_visual_config` 管产品分类颜色、图标、光晕 | 新增“分类视觉”专业配置区 |
| 首页配置 | `home_layout`、`home_widget` 控制首页布局和组件 | 新增“首页体验”专业配置区 |

## 二、设计目标

### 2.1 产品目标

一句话：

**Style Settings 应该像专业设计控制台，而不是配置表单。**

目标体验：

1. 管理员进入页面时，立刻看到“当前系统正在使用什么样式”。
2. 点击任一主题、色彩、布局、字号、首页组件开关后，系统立即响应。
3. 保存不再是用户理解生效的前提；保存应变成后台状态提示。
4. 回到页面时，所有选中项必须来自当前已保存配置，不允许回到默认假象。
5. Dict Management 中被保护的 UI 配置，必须在 Style Settings 中有对应专业入口。

### 2.2 视觉目标

| 目标 | 说明 |
|------|------|
| 专业后台感 | 克制、清晰、信息密度适中，不做营销页式大视觉 |
| 操作路径短 | 常用操作 1-2 次点击完成 |
| 层级清楚 | 品牌、色彩、排版、布局、首页、分类视觉、版本分区明确 |
| 状态可见 | 当前生效、保存中、已保存、失败回滚都有明确反馈 |
| 预览可信 | 预览和真实系统使用同一份 `draftConfig` / CSS 变量 |
| 响应式 | PC 三栏、窄屏双栏、移动端单栏分段切换 |

### 2.3 开发目标

| 目标 | 说明 |
|------|------|
| 状态单源 | 选中状态从服务端当前配置派生，不再散落多个默认 ref |
| 即时应用 | UI 操作先更新本地 CSS 变量，再后台保存 |
| 失败可回退 | 保存失败后恢复到上一次服务端配置 |
| 组件拆分 | `StyleSettings.vue` 只做页面装配 |
| 配置全覆盖 | 覆盖 `PROTECTED_CATEGORIES` 中所有 UI/视觉配置 |
| 文档可验收 | 每个配置域都有交付物和验收标准 |

### 3.1 二级分组展示

Style Settings 必须采用“一级导航 + 二级分组”的信息架构。一级导航回答“我要改哪一类体验”，二级分组回答“这一类里面具体改什么”。不要做三级导航，避免配置迷宫。

| 一级分类 | 二级分组 | 常用操作 | 高级/折叠项 |
|----------|----------|----------|-------------|
| 总览 | 当前方案、保存状态、快捷操作、配置健康检查 | 恢复默认、历史版本、导出配置 | 配置诊断详情 |
| 品牌 | 系统名称、Logo、Logo 尺寸、导航品牌预览 | 上传 Logo、移除 Logo、恢复默认名称 | 登录页品牌预览 |
| 色彩 | 色彩方案、价格涨跌色、图表色板、高级自定义 | 应用方案、复制色值、恢复方案默认色 | 9 色图表色板编辑 |
| 排版 | 字体族、字号预设、高级字号、阅读预览 | 应用字号预设、恢复标准字号 | 单项字号输入 |
| 布局 | 全局布局、导航模式、卡片样式、页面密度 | 应用布局、恢复经典布局 | 阴影强度、圆角细节 |
| 首页体验 | 首页布局、重点指标、组件显隐、组件排序 | 开关组件、调整数量、上移/下移 | 组件参数 JSON 只读查看 |
| 分类视觉 | 分类选择、颜色配置、图标配置、深色模式 | 修改色板、选择图标、预览卡片 | 深色模式颜色 |
| 版本恢复 | 历史版本、版本详情、回滚、默认值 | 回滚、恢复默认 | 导出版本快照 |

### 3.2 二级分组展示原则

| 原则 | 说明 |
|------|------|
| 常用在前 | 每个一级分类的前两个二级分组必须是最高频操作 |
| 高级折叠 | 复杂配置默认收起，不打扰日常使用 |
| 状态前置 | 每个二级分组标题右侧显示当前状态，如“标准字号”“已启用 4 个组件” |
| 操作就地 | 操作按钮放在对应分组内，不集中堆在页面底部 |
| 预览联动 | 中央配置变更后，右侧预览必须立即响应 |
| 无裸 JSON | 除只读诊断外，不让管理员直接编辑 JSON |

## 四、响应式状态模型

### 4.1 核心原则

**修改先进入临时预览态，必须点击保存后才正式生效；不保存离开页面时，不改变系统当前已保存样式。**

管理员在 Style Settings 中选择主题、色彩、字体、布局、首页组件或分类视觉时，页面应立即展示临时预览效果，但这只是当前配置页的 `draftConfig`。只有点击顶部固定的“保存”按钮并保存成功后，才更新服务端配置、全局真实样式和历史版本。这样可以避免误触导致系统全局样式立刻变化，也符合后台配置中心的可控性要求。

必须明确区分三种体验：

| 体验 | 定义 |
|------|------|
| 临时预览 | 只在 Style Settings 页面和右侧预览区显示，不影响其他页面真实样式 |
| 已修改未保存 | `draftConfig` 与 `serverConfig` 不一致，顶部显示“有未保存修改” |
| 已保存生效 | 点击保存成功后，`serverConfig`、`draftConfig`、`appliedConfig` 一致，刷新页面仍保持该状态 |

### 4.2 三层状态

建议在 `useStyleSettingsWorkbench.ts` 中维护三层状态：

```typescript
interface StyleWorkbenchState {
  serverConfig: StyleConfig        // 最近一次服务端确认的配置
  draftConfig: StyleConfig         // 当前页面正在展示和操作的配置
  appliedConfig: StyleConfig       // 当前系统真实生效配置，初始等于 serverConfig
  previewConfig: StyleConfig       // 当前 Style Settings 页面临时预览配置，等于 draftConfig
  saveStatus: 'idle' | 'dirty' | 'saving' | 'saved' | 'failed'
  lastSavedAt?: string
  lastError?: string
}
```

三层关系：

| 状态 | 来源 | 用途 |
|------|------|------|
| `serverConfig` | `GET /api/style/config` | 当前已保存基线，失败回滚依据 |
| `draftConfig` | 用户操作 | 页面选中态和表单值 |
| `previewConfig` | `draftConfig` 派生 | Style Settings 页面和右侧预览的临时视觉 |
| `appliedConfig` | 保存成功后的 `serverConfig` | 当前系统真实生效视觉 |

### 4.3 操作流程

所有配置操作统一走一个入口：

```typescript
function patchDraft(patch: Partial<StyleConfig>) {
  patchDraftConfig(patch)
  previewConfig.value = clone(draftConfig.value)
  saveStatus.value = isEqual(draftConfig.value, serverConfig.value) ? 'idle' : 'dirty'
}

async function saveDraftConfig() {
  if (isEqual(draftConfig.value, serverConfig.value)) return

  saveStatus.value = 'saving'

  try {
    await updateStyleConfig(draftConfig.value)
    serverConfig.value = clone(draftConfig.value)
    appliedConfig.value = clone(draftConfig.value)
    applyThemeToCSS(appliedConfig.value)
    saveStatus.value = 'saved'
  } catch (error) {
    draftConfig.value = clone(serverConfig.value)
    previewConfig.value = clone(serverConfig.value)
    applyThemeToCSS(appliedConfig.value)
    saveStatus.value = 'failed'
  }
}

function discardDraft() {
  draftConfig.value = clone(serverConfig.value)
  previewConfig.value = clone(serverConfig.value)
  saveStatus.value = 'idle'
}
```

关键限制：

- `patchDraft()` 不允许调用保存接口。
- `patchDraft()` 不允许改变其他页面真实样式，只允许更新配置页局部预览。
- `saveDraftConfig()` 是唯一持久化入口。
- `discardDraft()` 用于取消修改、离开页面确认放弃、保存失败回滚。

### 4.4 不同操作的响应方式

| 操作 | 交互方式 | 生效方式 | 保存方式 |
|------|----------|----------|----------|
| 选择色彩方案 | 点击预设卡 | 立即更新右侧预览和配置页局部变量 | 点击“保存”后统一持久化 |
| 修改涨跌色 | color picker/input | 输入即更新右侧价格预览 | 点击“保存”后统一持久化 |
| 选择布局方案 | 点击布局缩略图 | 立即更新布局缩略预览，不影响真实页面 | 点击“保存”后统一持久化 |
| 选择字号预设 | 点击预设卡 | 立即更新配置页预览字体比例 | 点击“保存”后统一持久化 |
| 修改字体族 | 下拉选择 | 立即更新字体预览 | 点击“保存”后统一持久化 |
| 修改系统名称 | 输入框 | 输入即更新导航预览 | 点击“保存”后统一持久化 |
| 上传 Logo | 上传成功后进入临时 Logo 预览 | 点击“保存”后正式替换；取消则恢复旧 Logo |
| 首页组件显隐 | switch | 立即影响首页片段预览 | 点击“保存”后统一持久化 |
| 首页组件排序 | 上移/下移/拖拽 | 立即更新预览顺序 | 点击“保存”后统一持久化 |
| 分类视觉颜色 | 色板选择 | 立即影响产品卡片预览 | 点击“保存”后统一持久化 |
| 历史版本回滚 | 确认后 | 回滚成功立即生效 | 后端生成回滚版本 |

### 4.5 页面回显规则

进入 Style Settings 页面时必须：

1. 强制调用 `GET /api/style/config`，不要只读 `themeConfig` 默认值。
2. 调用 `GET /api/style/presets` 或分项预设接口。
3. 用服务端配置填充 `serverConfig` 和 `draftConfig`。
4. 从 `draftConfig.activeColorScheme`、`draftConfig.activeLayoutStyle`、`draftConfig.fontSizePreset` 派生选中项。
5. 如果服务端缺少某个 active key，使用后端默认值并立即在 UI 中标注“使用默认值”，不要假装是用户已选择。
6. 页面离开时如果 `draftConfig` 与 `serverConfig` 不一致，必须弹出“存在未保存修改，是否放弃”的确认。
7. 用户点击“取消修改”时，恢复为 `serverConfig`，并清除所有临时预览。

禁止：

```typescript
const selectedTheme = ref('theme_red_green')
const activeLayoutStyleKey = ref('')
```

推荐：

```typescript
const activeColorSchemeKey = computed(() => draftConfig.value.activeColorScheme)
const activeLayoutStyleKey = computed(() => draftConfig.value.activeLayoutStyle)
const activeFontPresetKey = computed(() => draftConfig.value.fontSizePreset)
```

## 五、功能分区方案

### 5.1 总览

目标：进入页面第一眼知道当前系统状态。

内容：

| 模块 | 内容 |
|------|------|
| 当前方案摘要 | 当前色彩方案、布局方案、字号方案、Logo 状态 |
| 保存状态 | 已保存 / 保存中 / 保存失败 / 已回滚 |
| 最近修改 | 修改人、修改时间、版本号 |
| 快捷操作 | 恢复默认、查看历史、回滚上版、导出当前配置 |
| 健康检查 | 是否有缺失配置、是否有旧字典保护项未承接 |

UI 建议：

```text
┌──────────────────────────────────────────────────────┐
│ 全局样式设置                         已保存 13:42    │
│ 当前：深矿蓝仪表盘 / 标准字号 / 红涨绿跌              │
│ [恢复默认] [历史版本] [导出配置]                      │
└──────────────────────────────────────────────────────┘
```

### 5.2 品牌

内容：

- 系统名称
- Logo 上传
- Logo 尺寸
- 导航栏品牌预览

便捷操作：

- 一键恢复系统默认名称
- 一键移除 Logo
- Logo 尺寸 segmented control：小 / 中 / 大 / 特大

响应式要求：

- 系统名称输入后 300ms 更新预览。
- Logo 上传成功立即刷新全局 Logo。
- Logo 尺寸点击后立即应用。

### 5.3 色彩

内容：

- 色彩方案预设
- 涨价色、跌价色、持平色
- 图表主色、预算线颜色
- 图表 9 色色板
- 自定义色高级区

便捷操作：

- 一键应用色彩方案
- 复制色值
- 恢复当前方案默认色
- 色盲友好检查提示

响应式要求：

- 点击方案后全局涨跌色、图表色立即变化。
- 手动改色时立即应用 CSS 变量，并 debounce 保存。
- 当前选中方案必须来自 `draftConfig.activeColorScheme`。

### 5.4 排版

内容：

- 标题字体
- 正文字体
- 数字字体
- 字号预设
- 高级字号编辑

便捷操作：

- 字号预设：紧凑 / 标准 / 大字体 / 无障碍
- 一键恢复标准字号
- 价格数字字体预览

响应式要求：

- 字体选择后全站文字立即变化。
- 字号预设选择后立即更新 CSS 变量。
- 高级字号输入要校验 `rem` 格式。

### 5.5 布局

内容：

- 顶部导航
- 左侧导航
- 深矿蓝仪表盘
- 极简卡片式
- 页面密度
- 卡片圆角
- 阴影强度

便捷操作：

- 布局缩略图选择
- PC / 移动预览切换
- 一键恢复经典布局

响应式要求：

- 布局方案点击后全局导航、页面背景、卡片圆角等立即变化。
- 如果某布局需要刷新路由才能完全生效，页面必须提示“布局已保存，刷新后完整生效”，但 CSS 变量仍要立即变化。

### 5.6 首页体验

对应受保护分类：

- `home_layout`
- `home_widget`

应纳入 Style Settings，而不是留在 Dict Management。

内容：

| 配置 | 来源 | UI 控件 |
|------|------|---------|
| 首页布局模式 | `home_layout.layout_mode` | 分段控件 |
| PC 卡片列数 | `home_layout.card_columns` | stepper / slider |
| 移动端卡片列数 | `home_layout.card_columns_mobile` | stepper |
| 重点产品数量 | `home_layout.featured_product_count` | stepper |
| 是否显示趋势图 | `home_layout.show_trend_chart` | switch |
| 是否显示预警区 | `home_layout.show_alerts` | switch |
| 组件显隐 | `home_widget.*.enabled` | switch |

### 11.2 失败回滚

保存失败时：

1. 弹出轻提示。
2. `draftConfig` 回退到 `serverConfig`。
3. 重新调用 `applyThemeToCSS(serverConfig)`。
4. 对失败控件显示短暂错误状态。

## 十五、风险与处理

| 风险 | 处理 |
|------|------|
| 自动保存频繁请求 | debounce + 合并 patch + 保存队列 |
| 用户连续快速切换方案 | 只保留最后一次操作，前序请求结果过期丢弃 |
| 保存失败造成状态混乱 | 统一失败回滚到 `serverConfig` |
| 旧主题和新色彩方案并存 | 旧主题作为兼容入口，主 UI 强调色彩方案 |
| `home_layout` 仍在 dict 中 | 短期专业 API 代理读写，长期迁入 `sys_style_config` |
| `category_visual_config` JSON 复杂 | 使用 schema 表单，不开放裸 JSON |
| 预览和真实系统不一致 | 预览与 `applyThemeToCSS()` 共用 `draftConfig` |

---

## 十六、最终定义

完成后，Style Settings 的定位应变为：

```text
Style Settings = 全局品牌 + 色彩 + 排版 + 布局 + 首页体验 + 分类视觉 + 版本恢复 的响应式配置工作台
```

一句话验收：

**用户选中什么，系统立即变成什么；用户再次回来，页面准确显示当前系统正在使用什么；Dict Management 保护起来的 UI 配置，在 Style Settings 都能被专业、可视化地管理。**
