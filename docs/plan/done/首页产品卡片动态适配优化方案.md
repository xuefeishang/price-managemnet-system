# 首页产品卡片动态适配优化方案

**创建日期：2026-05-20**  
**适用范围：** `frontend/src/views/Home.vue` 首页 PC/移动端产品卡片、重点关注指标、产品列表、价格显示、趋势徽标、迷你图表  
**目标：** 保留当前首页字体风格和视觉气质，在不同显示器分辨率、窗口宽度、产品名称长度、价格位数差异下，让产品外框与文字动态适配，避免错行、错位、挤压和视觉失衡。

---

## 一、背景与问题判断

当前 Home 页面整体字体风格已经符合预期，问题主要不是“字体不好看”，而是**布局适配机制不够稳**。

从 `Home.vue` 现有结构看，主要风险集中在以下位置：

| 区域 | 当前表现 | 风险 |
|------|----------|------|
| PC 产品网格 | `product-grid-pc` 由 `gridCols` 动态控制列数 | 列数变化后，单卡宽度差异较大，内部字体和图表仍按固定尺寸展示 |
| 产品卡片外框 | `.product-card-pc` 使用 `min-height: 160px` | 产品名、规格、价格、趋势徽标同时较长时，内容会挤压 |
| 产品名称 | `.product-name` 单行 `nowrap + ellipsis` | 长名称虽然省略，但无法根据容器宽度自然展示两行，视觉信息损失大 |
| 价格文字 | `.price-value` 固定 `2.25rem` | 窄卡、大价格位数、多字符币种时容易压缩图表或单位 |
| 趋势徽标 | `.trend-badge` 固定 padding 与 `white-space: nowrap` | 宽度不足时会挤压产品名，造成标题行失衡 |
| 迷你图表 | `.chart-area` 固定 `80px x 40px` | 窄卡下图表占用过多，宽卡下又显得偏小 |
| 移动重点关注卡片 | `.home-featured-item-mobile` 固定 `min-width: 160px` | 不同手机宽度下卡片密度不稳定 |

核心结论：

- 不建议改变当前字体族、字号层级和视觉风格。
- 应把适配重点放在：**容器宽度感知、内容长度感知、卡片内部区域弹性、价格文字上限/下限控制、文本换行策略**。
- 字体不能简单按视口宽度线性缩放，应使用容器断点、CSS 变量和少量内容长度分级来控制视觉状态。

---

## 二、优化目标

### 2.1 视觉目标

1. 产品卡片外框能随屏幕宽度和列数自然伸缩。
2. 产品名称在空间充足时尽量完整展示，空间不足时优雅省略。
3. 重点关注指标卡片比普通产品卡片更突出，但不因价格位数或名称长度错位。
4. 价格数字保持当前醒目的金融数据感，但在窄卡中自动降级为紧凑档。
5. 趋势徽标、单位、迷你图表不与产品名和价格互相挤压。
6. PC 端、笔记本、外接大屏、移动端都保持稳定的视觉秩序。

### 2.2 技术目标

| 目标 | 实现方向 |
|------|----------|
| 卡片外框动态 | CSS Grid `auto-fit/minmax` + 卡片容器查询 |
| 文字动态 | 容器断点切换字号档位 + `line-clamp` + 长词断行保护 |
| 价格动态 | 价格区域独立布局，数字使用最大/最小字号边界 |
| 图表动态 | 图表尺寸由卡片宽度档位决定 |
| 代码可维护 | 抽出首页产品卡片组件，减少 PC/移动/重点关注重复模板 |
| 验收可量化 | 明确分辨率、长文本、长价格、移动端截图检查标准 |

## 三、设计原则

### 3.1 保留字体风格，不做粗暴缩放

当前首页字体风格已经满意，本次不改：

- `--font-body`
- `--font-heading`
- `--font-mono`
- 当前字重关系
- 当前价格数字的主视觉层级

本次只调整：

- 不同卡片宽度下使用哪个字号档。
- 文本允许一行还是两行。
- 内容过长时如何省略或换行。
- 外框如何自动伸缩。

### 3.2 以卡片容器为适配单位

不建议用 `vw` 直接控制字体大小，因为同一个视口下，侧边栏、列数、搜索区、外层容器都会影响卡片真实宽度。

推荐做法：

```css
.product-card-pc {
  container-type: inline-size;
}

@container (max-width: 300px) {
  .card-title-row .product-name {
    -webkit-line-clamp: 2;
  }
}
```

适配逻辑以“卡片自己有多宽”为准，而不是以“浏览器窗口有多宽”为准。

### 3.3 文本分级，而不是无限缩小

文字最多分为 3 个显示档位：

| 档位 | 使用场景 | 处理方式 |
|------|----------|----------|
| 舒展档 | 大屏、宽卡 | 产品名最多 2 行，价格大字号，显示图表 |
| 标准档 | 常规笔记本、3-4 列 | 产品名 1-2 行，价格标准字号，显示图表 |
| 紧凑档 | 窄卡、移动端 | 产品名最多 2 行，价格降一档，图表缩小或移到下一行 |

不允许把文字缩到不可读，也不允许为了强行不换行而破坏外框。

## 四、推荐实现方案

### 4.1 产品网格改造

当前：

```vue
<div class="product-grid-pc" :style="{ gridTemplateColumns: `repeat(${gridCols}, 1fr)` }">
```

建议改造方向：

```css
.product-grid-pc {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(var(--home-card-min-width), 1fr));
  gap: var(--spacing-md);
  align-items: stretch;
}

.product-grid-pc.featured {
  --home-card-min-width: 300px;
}

.product-section-pc .product-grid-pc {
  --home-card-min-width: 260px;
}
```

说明：

- `gridCols` 可以保留作为 Style Settings 或 HomeConfig 的最大列数控制，但不要让它成为唯一布局依据。
- 默认优先让 CSS Grid 根据可用宽度自动决定列宽。
- 如果必须限制最大列数，可在外层增加 CSS class 或 CSS 变量，而不是为每次分辨率手写列数。

可选增强：

```css
@media (min-width: 1800px) {
  .pc-home {
    max-width: 1680px;
  }
}
```

外接大屏时可适度放宽首页最大宽度，避免 1920/2560 屏幕下卡片过窄或页面留白过多。

### 4.2 卡片外框动态化

建议为产品卡片建立统一卡片变量：

```css
.product-card-pc {
  container-type: inline-size;
  --card-padding: var(--spacing-lg);
  --card-min-height: 164px;
  --card-title-lines: 1;
  --card-price-size: 2rem;
  --card-chart-width: 80px;
  --card-chart-height: 40px;

  min-height: var(--card-min-height);
  padding: var(--card-padding);
}

.product-card-pc.featured {
  --card-min-height: 184px;
  --card-price-size: 2.25rem;
}
```

容器断点：

```css
@container (max-width: 320px) {
  .product-card-pc {
    --card-padding: var(--spacing-md);
    --card-title-lines: 2;
    --card-price-size: 1.65rem;
    --card-chart-width: 64px;
    --card-chart-height: 32px;
  }
}

@container (min-width: 420px) {
  .product-card-pc {
    --card-title-lines: 2;
    --card-price-size: 2.25rem;
    --card-chart-width: 96px;
    --card-chart-height: 44px;
  }
}
```

验收重点：

- 卡片外框高度可以随内容略微增长，但同一行卡片视觉高度要稳定。
- 内容不能溢出卡片边界。
- hover 动效不能造成布局重排。

### 4.3 产品名称动态展示

当前产品名是单行省略：

```css
white-space: nowrap;
text-overflow: ellipsis;
```

建议改为“按容器宽度决定一行或两行”：

```css
.card-title-row .product-name {
  min-width: 0;
  display: -webkit-box;
  -webkit-line-clamp: var(--card-title-lines);
  -webkit-box-orient: vertical;
  overflow: hidden;
  text-overflow: ellipsis;
  white-space: normal;
  overflow-wrap: anywhere;
}
```

规则：

- 普通宽度：优先 1 行，保持清爽。
- 窄卡或长名称：允许 2 行，避免信息损失过大。
- 超长无空格名称：允许 `overflow-wrap: anywhere`，避免撑破卡片。
- 鼠标悬浮时可用浏览器 `title` 或轻量 tooltip 显示完整名称。

模板建议：

```vue
<span class="product-name" :title="product.name">{{ product.name }}</span>
```

### 4.4 价格区域动态展示

价格是首页最重要的信息，应优先保证完整展示。

建议结构：

```css
.price-row {
  min-width: 0;
  display: flex;
  align-items: baseline;
  flex-wrap: wrap;
  column-gap: 2px;
  row-gap: 2px;
}

.price-value {
  max-width: 100%;
  font-size: var(--card-price-size);
  font-variant-numeric: tabular-nums;
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}

.price-unit {
  flex-shrink: 0;
}
```

重点：

- 价格数字使用 `tabular-nums`，保证数字宽度稳定。
- 价格值不随视口无限缩放，而是在卡片档位内切换。
- 单位可以换到价格下方或右侧第二行，不能挤压价格主体。
- 特别长价格如 `¥123,456,789.00` 应优先完整，必要时缩小价格字号档位。

### 4.5 趋势徽标自适应

趋势徽标应保护产品名空间。

建议：

```css
.trend-badge {
  max-width: 42%;
  overflow: hidden;
  text-overflow: ellipsis;
}

@container (max-width: 320px) {
  .trend-badge {
    padding: 3px 6px;
    max-width: 36%;
  }
}
```

如果后续允许结构调整，建议把趋势徽标从标题行移到价格区右上角或价格区旁边，让产品名拥有更稳定的行宽。

重点关注指标卡片可保留趋势徽标更强的视觉权重，普通产品列表卡片则可以更紧凑。

### 4.6 迷你图表自适应

当前 `.chart-area` 固定 `80px x 40px`。建议改为变量控制：

```css
.chart-area,
.mini-chart {
  width: var(--card-chart-width);
  height: var(--card-chart-height);
}
```

窄卡策略：

- 图表缩小到 `64px x 32px`。
- 如果价格过长，图表可换到下一行右侧。
- 极窄情况下普通产品卡片可隐藏图表，重点关注指标仍保留。

### 4.7 移动端重点关注卡片优化

当前移动端重点关注卡片：

```css
.home-featured-item-mobile {
  min-width: 160px;
  width: calc(50vw - var(--spacing-lg));
  max-width: 200px;
}
```

建议：

```css
.home-featured-item-mobile {
  min-width: min(72vw, 180px);
  width: clamp(168px, 46vw, 220px);
  container-type: inline-size;
}
```

移动端规则：

- 375/390 宽度：一屏露出约 1.7-2 张重点卡片。
- 430 宽度：一屏露出约 2 张卡片。
- 产品名最多 2 行。
- 价格字号比 PC 小一档，但不能低于 `1.25rem`。
- 普通产品列表保持信息密度，避免卡片过高。

## 五、代码结构建议

### 5.1 抽出统一产品卡片组件

当前 `Home.vue` 中 PC 重点关注、PC 产品列表、移动重点关注、移动产品列表存在重复结构。建议抽出：

```text
frontend/src/components/home/HomeProductCard.vue
frontend/src/components/home/HomeProductGrid.vue
frontend/src/composables/useHomeProductCard.ts
```

组件职责：

| 文件 | 职责 |
|------|------|
| `HomeProductCard.vue` | 统一展示产品名称、规格、价格、单位、趋势、图表 |
| `HomeProductGrid.vue` | 管理产品网格、重点关注布局、空状态 |
| `useHomeProductCard.ts` | 计算价格展示、趋势状态、长文本档位、是否显示图表 |

组件参数建议：

```typescript
type HomeProductCardVariant = 'featured-pc' | 'list-pc' | 'featured-mobile' | 'list-mobile'

interface HomeProductCardProps {
  product: Product
  variant: HomeProductCardVariant
  priceText?: string
  unitText?: string
  trend?: {
    direction: 'up' | 'down' | 'flat'
    formattedDiff: string
  } | null
  chartOption?: unknown
  categoryStyle?: Record<string, string>
}
```

这样能避免四处重复维护 `.product-name`、`.price-value`、`.trend-badge` 的适配逻辑。

### 5.2 建立首页卡片专用 CSS 变量

建议在 `Home.vue` 或后续独立样式文件中定义：

```css
.home-page {
  --home-card-min-width: 260px;
  --home-card-featured-min-width: 300px;
  --home-card-title-lines: 1;
  --home-card-price-size: 2rem;
  --home-card-chart-width: 80px;
  --home-card-chart-height: 40px;
}
```

后续如果 Style Settings 要管理“首页展示密度”，可以只调整这些变量，而不需要改产品卡片内部结构。

### 5.3 内容长度感知

CSS 容器查询解决的是宽度问题，产品内容长度仍建议有轻量计算：

```typescript
const getNameDensity = (name: string) => {
  if (name.length >= 18) return 'long'
  if (name.length >= 10) return 'medium'
  return 'short'
}

const getPriceDensity = (priceText: string) => {
  if (priceText.length >= 12) return 'long'
  if (priceText.length >= 8) return 'medium'
  return 'short'
}
```

渲染 class：

```vue
<article
  class="home-product-card"
  :class="[
    `variant-${variant}`,
    `name-${nameDensity}`,
    `price-${priceDensity}`
  ]"
>
```

用途：

- 长产品名默认允许两行。
- 长价格自动使用紧凑价格字号。
- 不把所有卡片都降级，只有真正需要的内容降级。

### 5.4 UnoCSS 应用策略

本项目已经引入 UnoCSS，并在 `frontend/uno.config.ts` 中启用了 `presetUno`、`presetAttributify`、`mode: 'vue-scoped'`、CSS 变量主题绑定、语义化 shortcuts 和 `truncate-2` / `truncate-3` 自定义规则。本次 Home 卡片优化应主动使用这套能力，但不要把复杂卡片适配全部塞进原子类。

**推荐原则：UnoCSS 管结构和语义，scoped CSS 管容器查询和复杂状态。**

| 内容 | 推荐归属 | 说明 |
|------|----------|------|
| 页面/区块布局 | UnoCSS shortcuts | 如 `page-pc`、`section`、`header-row`、`grid-*` |
| 常规 flex/grid/gap | UnoCSS | 减少重复 scoped CSS |
| 卡片基础视觉 | UnoCSS shortcuts | 背景、圆角、边框、阴影、hover 基础态 |
| 字体/颜色/间距 token | UnoCSS theme + CSS 变量 | 继续复用 `--font-size-*`、`--spacing-*`、`--primary-color` |
| 容器查询 | scoped CSS | `@container` 规则不适合写成大量原子类 |
| 内容长度档位 | Vue class + scoped CSS | 如 `name-long`、`price-long` |
| 价格/图表动态尺寸 | scoped CSS 变量 | 如 `--card-price-size`、`--card-chart-width` |
| 分类视觉变量 | scoped CSS / inline style | 继续兼容 `useCategoryVisual.ts` |

#### 5.4.1 建议扩展 UnoCSS shortcuts

建议在 `frontend/uno.config.ts` 中增加首页卡片语义化 shortcuts：

```typescript
shortcuts: {
  'home-card': 'bg-white rounded-lg border border-gray-200 cursor-pointer transition-all overflow-hidden relative',
  'home-card-hover': 'hover:shadow-card-hover hover:-translate-y-1',
  'home-card-featured': 'border-2 border-primary',
  'home-card-title': 'font-semibold text-base text-gray-900 min-w-0',
  'home-card-spec': 'text-xs text-gray-400 min-w-0',
  'home-price': 'font-mono font-bold text-primary leading-none',
  'home-trend': 'inline-flex items-center rounded-md text-xs font-semibold shrink-0',
  'home-grid': 'grid gap-md items-stretch',
}
```

使用目标：

- `HomeProductCard.vue` 的模板表达更语义化。
- 卡片基础视觉统一收敛到 `uno.config.ts`。
- scoped CSS 只保留真正需要上下文和容器感知的规则。

#### 5.4.2 建议扩展 UnoCSS rules

当前已有 `truncate-2`、`truncate-3`，建议补充：

```typescript
rules: [
  ['truncate-1', {
    overflow: 'hidden',
    'text-overflow': 'ellipsis',
    'white-space': 'nowrap',
  }],
  ['break-anywhere', {
    'overflow-wrap': 'anywhere',
  }],
  ['container-inline', {
    'container-type': 'inline-size',
  }],
  ['numeric-tabular', {
    'font-variant-numeric': 'tabular-nums',
  }],
]
```

对应使用方式：

```vue
<article class="home-card home-card-hover container-inline flex flex-col gap-sm">
  <div class="flex items-start justify-between gap-sm">
    <span class="home-card-title break-anywhere" :title="product.name">
      {{ product.name }}
    </span>
    <span class="home-trend">{{ trendText }}</span>
  </div>

  <div class="mt-auto flex items-end justify-between gap-sm">
    <div class="min-w-0">
      <span class="home-price numeric-tabular">{{ priceText }}</span>
      <span class="text-xs text-gray-400">{{ unitText }}</span>
    </div>
  </div>
</article>
```

#### 5.4.3 不建议的 UnoCSS 用法

| 不建议做法 | 原因 | 替代方案 |
|------------|------|----------|
| 在模板中堆很长的原子类 | 影响可读性，后续难统一调整 | 抽成 `home-card` 等 shortcut |
| 用 UnoCSS 任意值写满卡片尺寸 | 容易形成新的硬编码 | 使用 CSS 变量和容器查询 |
| 用响应式断点替代容器查询 | 卡片真实宽度不一定等于视口宽度 | 页面级用 UnoCSS，卡片内部用 `@container` |
| 把分类视觉颜色写入 UnoCSS class | 分类颜色来自运行时数据 | 保持 CSS 变量或 inline style |
| 为每个卡片状态新增大量 shortcut | shortcut 失控后难维护 | 只沉淀跨组件复用的语义类 |

## 六、实施步骤

### 6.0 实施要求

本次优化属于前端 UI 适配优化，默认不改数据库、不改后端 API、不改字典服务。除非实施过程中发现现有字段无法表达必要信息，否则不得扩大到后端改造。

**必须遵守：**

| 要求 | 说明 | 验收方式 |
|------|------|----------|
| 保留字体风格 | 不更换 `font-family`，不改变首页当前字体气质 | 对比改造前后截图，字体观感一致 |
| 不使用视口线性缩放 | 不用 `font-size: xvw` 直接控制产品名、价格、徽标 | CSS 检查无首页卡片核心文字 `vw` 字号 |
| 优先容器适配 | 以卡片宽度为准做档位切换 | 存在 `container-type: inline-size` 或等价机制 |
| 文字有明确策略 | 产品名、规格、价格、单位、趋势徽标分别定义换行/省略规则 | 压力测试无撑破、重叠、错位 |
| 卡片外框稳定 | hover、图表加载、长文本出现时不改变网格结构 | 多断点截图同一行卡片无明显跳动 |
| 数据逻辑不变 | 不改价格计算、趋势计算、产品筛选、字典加载 | 现有首页功能回归通过 |
| PC/移动一起验收 | 不只看当前开发机分辨率 | 7.1 断点截图全部通过 |

**禁止做法：**

- 禁止把所有文本都改成更小字号来掩盖布局问题。
- 禁止把产品名永久单行省略作为唯一方案。
- 禁止让价格数字为了容器适配缩小到低于 `1.25rem`。
- 禁止让趋势徽标、图表、单位挤占产品名和价格主体空间。
- 禁止为了某个单一分辨率写死卡片宽度。
- 禁止在 `Home.vue` 中继续复制多套卡片样式而不抽象公共规则。

### 6.0.2 容器查询兜底要求

容器查询是首选方案，但需要提供兜底，避免兼容性或构建问题导致页面退化。

推荐写法：

```css
.product-card-pc {
  container-type: inline-size;
}

@container (max-width: 320px) {
  .product-card-pc {
    --card-price-size: 1.65rem;
    --card-title-lines: 2;
    --card-chart-width: 64px;
  }
}

@supports not (container-type: inline-size) {
  @media (max-width: 1200px) {
    .product-card-pc {
      --card-price-size: 1.65rem;
      --card-title-lines: 2;
      --card-chart-width: 64px;
    }
  }
}
```

兜底验收：

- 即使容器查询未生效，1024/1366 宽度下仍不发生明显重叠。
- 兜底只保证不破版，不要求达到容器查询下的最佳视觉。

## 七、验收标准

验收采用“硬性失败项 + 分辨率截图 + 内容压力测试 + 功能回归”四层标准。只要出现硬性失败项，本次优化不得通过。

### 7.0 硬性失败项

出现以下任一情况，视为验收失败：

| 失败项 | 判定标准 |
|--------|----------|
| 文字重叠 | 产品名、价格、单位、趋势徽标、图表任意两个元素发生视觉重叠 |
| 内容撑破卡片 | 文本或图表超出卡片边框可见区域 |
| 横向滚动异常 | PC 首页主体出现非预期横向滚动条 |
| 价格不可读 | 价格主体字号低于 `1.25rem` 或被省略到无法识别 |
| 产品名丢失 | 产品名完全不可见，或短产品名被错误截断 |
| 图表压价 | 迷你图表挤压价格，导致价格显示不完整 |
| 移动遮挡 | 移动端产品项与底部导航、横滑卡片发生遮挡 |
| 功能回归 | 产品点击、搜索、分类筛选、日期切换、刷新任一功能异常 |

## 九、开发注意事项

1. 不要把字体大小写成 `vw` 线性缩放，避免不同显示器下字体漂移。
2. 不要为了避免换行把所有文本都强制 `nowrap`，产品名应允许 1-2 行。
3. 不要让趋势徽标挤压产品名，窄卡时徽标必须让位。

5. 不要让 hover 的 `transform` 引发周边卡片布局重排。
6. 不要在多个模板中重复写卡片结构，后续应抽组件统一维护。
7. 不要改动产品、价格、字典接口；本次优化优先限定在前端视觉与组件层。
8. 如果后续接入 Style Settings 的首页密度配置，只暴露“舒展/标准/紧凑”三个选项，不暴露复杂 CSS 字段给管理员。
