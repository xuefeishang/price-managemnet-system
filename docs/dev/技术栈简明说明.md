## 一、前端技术

### 1.1 Vue 3 — 响应式 UI 框架

**核心原理：** Vue 3 使用 ES6 Proxy 实现响应式系统。当你修改一个响应式变量（`ref` / `reactive`），Vue 自动追踪依赖并重新渲染相关 DOM。

**项目中的使用模式 — Composition API + `<script setup>`：**

```vue
<script setup lang="ts">
import { ref, onMounted, computed } from 'vue'

// 响应式状态
const products = ref<Product[]>([])
const loading = ref(false)
const searchQuery = ref('')

// 计算属性 — 依赖变化时自动重新计算
const filteredProducts = computed(() =>
  products.value.filter(p => p.name.includes(searchQuery.value))
)

// 生命周期钩子
onMounted(() => {
  loadProducts()
})

// 方法
const loadProducts = async () => {
  loading.value = true
  try {
    const response = await getProducts({ page: 0, size: 100 })
    products.value = response.data.content || []
  } catch (error) {
    console.error('Failed to load products:', error)
  } finally {
    loading.value = false
  }
}
</script>
```

**为什么用 `ref` 而不是 `reactive`：**
- `ref` 可以替换整个值（`products.value = newList`），`reactive` 不能
- `ref` 对基本类型和对象都适用，`reactive` 只适用于对象
- 项目统一使用 `ref` 作为状态声明方式

**模板中的双端适配（PC/移动端）：**

```vue
<template>
  <!-- PC 布局 -->
  <template v-if="isPCLayout">
    <div class="table-container">...</div>
  </template>
  <!-- 移动端布局 -->
  <template v-else>
    <div class="card-container">...</div>
  </template>
</template>
```

`isPCLayout` 来自 `useLayout()` composable，基于 `window.innerWidth >= 1024` 判断。

### 1.5 Pinia — 状态管理

**核心概念：** Pinia 是 Vue 3 官方状态管理库，替代 Vuex。使用 Composition API 风格。

**项目中的两个 Store：**

#### useUserStore — 用户认证状态

```typescript
// src/store/useUserStore.ts
export const useUserStore = defineStore('user', () => {
  // 状态
  const user = ref<User | null>(null)
  const token = ref<string | null>(localStorage.getItem('token'))

  // 计算属性
  const isAuthenticated = computed(() => !!token.value)
  const isAdmin = computed(() => user.value?.role === 'ADMIN')
  const canEdit = computed(() => user.value?.role === 'ADMIN' || user.value?.role === 'EDITOR')

  // 操作
  const loginAction = async (data: LoginRequest) => {
    const response = await login(data)
    token.value = response.data.token
    localStorage.setItem('token', response.data.token)
    user.value = { ... } // 从登录响应填充
  }

  const logoutAction = () => {
    user.value = null
    token.value = null
    localStorage.removeItem('token')
    // JWT 无状态，无需调用后端登出接口
  }

  const fetchProfile = async () => {
    const response = await getProfile()
    user.value = response.data
  }

  return { user, token, isAuthenticated, isAdmin, canEdit, loginAction, logoutAction, fetchProfile }
})
```

**关键设计：** `token` 初始化时从 `localStorage` 读取，实现页面刷新后保持登录状态。

#### useMenuStore — 菜单状态

```typescript
export const useMenuStore = defineStore('menu', () => {
  const visibleMenus = ref<MenuItem[]>([])
  const version = ref(0)  // 版本号，变更时自增触发响应式更新

  const loadVisibleMenus = async () => {
    const role = userStore.user?.role || 'VIEWER'
    const response = await getVisibleMenus(role)
    visibleMenus.value = response.data
    version.value++  // 触发 Layout 重新渲染
  }

  return { visibleMenus, version, loadVisibleMenus }
})
```

**为什么需要 `version`：** 当管理员修改菜单配置后，需要刷新所有用户的侧边栏。`Layout` 组件 watch `version`，变化时重新渲染菜单。

### 1.6 Vue Router — 路由与权限守卫

**路由配置：** 所有认证页面嵌套在 `Layout` 组件下，通过 `meta` 字段控制权限。

```typescript
// src/router/index.ts
const routes = [
  { path: '/login', component: Login, meta: { requiresAuth: false } },
  {
    path: '/',
    component: Layout,
    meta: { requiresAuth: true },
    children: [
      { path: 'home', component: () => import('../views/Home.vue') },
      { path: 'products', component: () => import('../views/Products.vue') },
      { path: 'users', component: () => import('../views/UserManagement.vue'),
        meta: { adminOnly: true } },           // 仅 ADMIN
      { path: 'price-maintenance', component: () => import('../views/PriceMaintenance.vue'),
        meta: { editorOnly: true } },          // ADMIN + EDITOR
    ]
  }
]
```

**导航守卫 — 前后端双重权限验证：**

```typescript
router.beforeEach(async (to, _from, next) => {
  // 1. 设置页面标题
  if (to.meta.title) document.title = `${to.meta.title} - 价格管理系统`

  // 2. 非认证页面直接放行
  if (!to.meta.requiresAuth) return next()

  // 3. 检查 Token 是否存在
  if (!userStore.isAuthenticated || !userStore.token) {
    showToast('请先登录')
    return next('/login')
  }

  // 4. 首次进入：拉取用户信息
  if (!userStore.user) {
    try {
      await userStore.fetchProfile()
    } catch {
      userStore.logoutAction()  // Token 已失效
      return next('/login')
    }
  }

  // 5. 前端角色校验（后端也有 @PreAuthorize 兜底）
  if (to.meta.adminOnly && !userStore.isAdmin) {
    showToast('您没有权限访问该页面')
    return next('/home')
  }
  if (to.meta.editorOnly && !userStore.canEdit) {
    showToast('您没有权限执行此操作')
    return next('/products')
  }

  next()
})
```

**关键理解：** 前端路由守卫是**用户体验层**的权限控制（避免用户看到无权页面），真正的安全在**后端 `@PreAuthorize`**。即使绕过前端守卫直接调用 API，后端也会拒绝。

### 1.7 Axios — HTTP 请求层

**架构设计：** 统一的请求/响应拦截器处理认证、错误提示、慢请求检测。

```typescript
// src/utils/http.ts
const instance = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL || '',
  timeout: 30000,
})

// 请求拦截器 — 自动附加 Token
instance.interceptors.request.use(config => {
  const userStore = useUserStore()
  if (userStore.token) {
    config.headers.Authorization = `Bearer ${userStore.token}`
  }
  config.metadata = { startTime: Date.now() }  // 记录请求开始时间
  return config
})

// 响应拦截器 — 解包 + 错误处理
instance.interceptors.response.use(
  response => {
    // 慢请求检测 (>3秒)
    const duration = Date.now() - (response.config.metadata?.startTime || 0)
    if (duration > 3000) console.debug(`请求耗时: ${duration}ms - ${response.config.url}`)

    const data = response.data
    if (data.code === 200) return data  // 解包：调用方直接拿到 ApiResponse<T>
    else { showToast(data.message); return Promise.reject(data) }
  },
  error => {
    if (error.response?.status === 401) {
      // 不弹提示，由路由守卫处理跳转
      return Promise.reject(error)
    }
    // 403/404/500 等统一弹 Toast
    showToast(getErrorMessage(error))
    return Promise.reject(error)
  }
)
```

**解包机制详解：**

```
后端返回:  { code: 200, message: "成功", data: {...}, timestamp: 123 }
                ↓
Axios 原始:  response.data = { code: 200, message: "成功", data: {...}, timestamp: 123 }
                ↓
拦截器解包:  返回 data 本身 → { code: 200, message: "成功", data: {...}, timestamp: 123 }
                ↓
API 函数:    const response = await getProducts(params)
             response.data = 实际业务数据 (PageResponse<Product>)
```

**API 模块组织：**


### 1.8 useDict — 字典服务（核心 Composable）

**设计意图：** 所有编码值的显示名称从后端动态获取，前端绝不硬编码中文标签。

**缓存机制：**

```typescript
// src/composables/useDict.ts
const dictCache = reactive(new Map<string, SysDict[]>())  // 响应式 Map
const loaded = ref(false)

// 一次性加载全部字典 — 页面 onMounted 中调用
export const loadAllDicts = async () => {
  if (loaded.value) return  // 防重复加载
  const response = await getDicts()  // GET /api/dict
  allDicts.value = response.data

  // 按 category 分组存入 Map
  const map = new Map<string, SysDict[]>()
  for (const dict of response.data) {
    const list = map.get(dict.category) || []
    list.push(dict)
    map.set(dict.category, list)
  }
  map.forEach((value, key) => dictCache.set(key, value))
  loaded.value = true
}
```

**查找函数 — 同步读取，无网络请求：**

```typescript
// 获取字典值: getDictValue('currency', 'CNY') → '¥'
export const getDictValue = (category: string, dictKey: string): string =>
  getDictItem(category, dictKey)?.dictValue || dictKey

export const getDictOptions = (category: string) =>
  getActiveDictByCategory(category).map(d => ({

export const getRoleLabel = (key: string) => getDictValue('user_role', key)
export const getCurrencySymbol = (key: string) => getDictValue('currency', key)
```

## 二、后端技术

### 2.1 Spring Boot 4.0.6 — 核心框架

**分层架构与请求处理流程：**

```
HTTP 请求
  ↓
JwtAuthenticationFilter (提取 Token, 设置 SecurityContext)
  ↓
Controller (@RestController, 接收请求, 参数校验)
  ↓
Service (@Service, @Transactional, 业务逻辑)
  ↓
Repository (JpaRepository, 数据访问)
  ↓
Hibernate (ORM, 生成 SQL)
  ↓
MySQL (执行 SQL, 返回数据)
  ↓
原路返回: Entity → DTO → Result<T> → JSON
```

**Controller 层实际代码模式：**

```java
@RestController
@RequestMapping("/api/products")
@RequiredArgsConstructor  // Lombok 构造器注入
public class ProductController {

    private final ProductService productService;

    @GetMapping
    @PreAuthorize("hasAnyRole('ADMIN', 'EDITOR', 'VIEWER')")  // 方法级权限
    public Result<Page<Product>> getProducts(
            @RequestParam(defaultValue = "0") int page,
            @RequestParam(defaultValue = "10") int size,
            @RequestParam(required = false) String keyword,
            @RequestParam(required = false) Long categoryId,
            @RequestParam(required = false) CommonStatus status,
            @RequestParam(required = false, defaultValue = "id") String sortBy,
            @RequestParam(required = false, defaultValue = "asc") String sortDirection) {
        Page<Product> result = productService.getProducts(page, size, keyword, categoryId, status, sortBy, sortDirection);
        return Result.success("查询成功", result);
    }

    @PostMapping
    @PreAuthorize("hasAnyRole('ADMIN', 'EDITOR')")
    public Result<Product> createProduct(@Valid @RequestBody Product product) {
        Product created = productService.createProduct(product);
        return Result.success("创建成功", created);
    }
}
```

**统一响应包装 — `Result<T>`：**

```java
@Data
public class Result<T> {
    private Integer code;      // 200=成功, 400=参数错误, 401=未认证, 403=无权限
    private String message;    // 提示信息
    private T data;            // 业务数据 (泛型)
    private long timestamp;    // 时间戳

    public static <T> Result<T> success(String message, T data) {
        Result<T> r = new Result<>();
        r.setCode(200);
        r.setMessage(message);
        r.setData(data);
        r.setTimestamp(System.currentTimeMillis());
        return r;
    }

    public static <T> Result<T> error(Integer code, String message) {
        Result<T> r = new Result<>();
        r.setCode(code);
        r.setMessage(message);
        r.setTimestamp(System.currentTimeMillis());
        return r;
    }
}
```

**Service 层 — 分页查询构造：**

```java
@Service
@RequiredArgsConstructor
public class ProductService {

    private final ProductRepository productRepository;

    @Transactional(readOnly = true)
    public Page<Product> getProducts(int page, int size, String keyword,
                                      Long categoryId, CommonStatus status,
                                      String sortBy, String sortDirection) {
        Sort.Direction direction = "desc".equalsIgnoreCase(sortDirection)
            ? Sort.Direction.DESC : Sort.Direction.ASC;
        Sort sort = Sort.by(direction, sortBy != null ? sortBy : "id");
        Pageable pageable = PageRequest.of(page, size, sort);

        // 根据参数组合选择不同的查询方法
        if (keyword != null && categoryId != null) {
            return productRepository.findByNameContainingAndCategoryIdAndStatus(
                keyword, categoryId, status, pageable);
        }
        // ... 其他组合
        return productRepository.findAll(pageable);
    }
}
```

**Entity 层 — JPA 注解与数据库映射：**

```java
@Entity
@Table(name = "product")           // 映射到 product 表
@Data                              // Lombok: getter/setter/toString/equals/hashCode
public class Product {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)  // 自增主键
    private Long id;

    @Column(name = "name", nullable = false)             // NOT NULL 列
    private String name;

    @ManyToOne(fetch = FetchType.LAZY)                   // 懒加载关联
    @JoinColumn(name = "category_id")                    // 外键列
    private ProductCategory category;

    @Version                                             // 乐观锁
    private Long version;

    @CreationTimestamp                                   // 自动填充创建时间
    private LocalDateTime createdTime;

    @UpdateTimestamp                                     // 自动填充更新时间
    private LocalDateTime updatedTime;

    @Transient                                           // 不映射到数据库
```

**SecurityConfig 关键配置：**

```java
@Configuration
@EnableWebSecurity
@EnableMethodSecurity  // 启用 @PreAuthorize
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http,
                                                    JwtAuthenticationFilter jwtFilter) throws Exception {
        http
            .csrf(csrf -> csrf.disable())                          // 禁用 CSRF (JWT 无状态)
            .cors(cors -> cors.configurationSource(corsConfig())) // CORS 配置
            .sessionManagement(s -> s.sessionCreationPolicy(
                SessionCreationPolicy.STATELESS))                 // 无状态 Session
            .authorizeHttpRequests(auth -> auth
                .requestMatchers(PUBLIC_PATHS).permitAll()        // 公开路径
                .anyRequest().authenticated()                      // 其余需认证
            )
            .exceptionHandling(ex -> ex
                .authenticationEntryPoint((req, res, e) -> {
                    // 返回 401 JSON: {"code":401,"message":"未登录或登录已过期"}
                })
                .accessDeniedHandler((req, res, e) -> {
                    // 返回 403 JSON: {"code":403,"message":"没有权限访问该资源"}
                })
            )
            .addFilterBefore(jwtFilter,
                UsernamePasswordAuthenticationFilter.class);       // JWT Filter 位置

        return http.build();
    }
}
```

### 2.3 Refresh Token 机制

**设计目的：** JWT Access Token 有效期 24 小时，过期后用户需重新登录。Refresh Token 机制允许用户在 Access Token 过期后自动刷新，无需重新输入密码，提升用户体验。

**Token 类型与有效期：**

| Token 类型 | 有效期 | 存储位置 | 用途 |
|-----------|--------|---------|------|
| Access Token | 24 小时 | 前端 localStorage | API 请求认证 |
| Refresh Token | 7 天 | 前端 localStorage + 后端数据库 | 刷新 Access Token |

**刷新流程：**

```
┌─────────────────────────────────────────────────────────────┐
│                    Token 刷新流程                              │
│                                                              │
│  1. Access Token 过期 (401 响应)                              │
│     ↓                                                        │
│  2. 前端拦截器检测到 401                                       │
│     ↓                                                        │
│  3. 调用 POST /api/auth/refresh-token { refreshToken }       │
│     ↓                                                        │
│  4. 后端验证 RefreshToken:                                    │
│     - 检查数据库是否存在                                        │
│     - 检查是否已撤销 (revoked=false)                           │
│     - 检查是否过期 (expiryDate > now)                          │
│     ↓                                                        │
│  5. 验证通过 → 生成新 Access Token → 返回                       │
│     ↓                                                        │
│  6. 前端更新 localStorage，重试原请求                           │
│                                                              │
│  异常情况:                                                     │
│  - Refresh Token 不存在/已撤销/已过期 → 返回 401 → 跳转登录页    │
└─────────────────────────────────────────────────────────────┘
```

**后端实现核心代码：**

```java
// RefreshToken 实体
@Entity
@Table(name = "refresh_token")
public class RefreshToken {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @Column(name = "token", unique = true, length = 500)
    private String token;          // UUID 格式
    
    @Column(name = "user_id")
    private Long userId;
    
    @Column(name = "expiry_date")
    private LocalDateTime expiryDate;  // 7 天后过期
    
    @Column(name = "revoked")
    private boolean revoked = false;   // 登出时撤销
    
    public boolean isValid() {
        return !revoked && !isExpired();
    }
}

// RefreshTokenService
@Service
public class RefreshTokenService {
    
    public RefreshToken createRefreshToken(Long userId, String username) {
        refreshTokenRepository.deleteByUserId(userId);  // 删除旧 Token
        RefreshToken token = new RefreshToken();
        token.setToken(UUID.randomUUID().toString());
        token.setUserId(userId);
        token.setExpiryDate(LocalDateTime.now().plusDays(7));
        return refreshTokenRepository.save(token);
    }
    
    public String refreshAccessToken(String refreshTokenStr) {
        RefreshToken token = refreshTokenRepository.findByToken(refreshTokenStr)
            .orElseThrow(() -> new TokenRefreshException("刷新令牌不存在"));
        
        if (!token.isValid()) {
            throw new TokenRefreshException("刷新令牌无效");
        }
        
        User user = userRepository.findById(token.getUserId())
            .orElseThrow(() -> new TokenRefreshException("用户不存在"));
        
        return jwtUtil.generateToken(user.getId(), user.getUsername(), user.getRole().name());
    }
    
    public void revokeUserTokens(Long userId) {
        refreshTokenRepository.revokeAllByUserId(userId);
    }
}
```

**前端 Token 刷新拦截器：**

```typescript
// src/utils/http.ts
let isRefreshing = false
let failedQueue: Array<{ resolve: Function, reject: Function }> = []

instance.interceptors.response.use(
  response => response,
  async error => {
    const status = error.response?.status
    const url = error.config?.url || ''
    
    // 401 且非登录/刷新接口
    if (status === 401 && !url.includes('/auth/login') && !url.includes('/auth/refresh-token')) {
      if (isRefreshing) {
        // 正在刷新，加入队列等待
        return new Promise((resolve, reject) => {
          failedQueue.push({ resolve, reject })
        }).then(token => {
          error.config.headers.Authorization = `Bearer ${token}`
          return instance(error.config)
        })
      }
      
      isRefreshing = true
      try {
        const newToken = await userStore.refreshAccessToken()
        if (newToken) {
          processQueue(null, newToken)
          error.config.headers.Authorization = `Bearer ${newToken}`
          return instance(error.config)
        }
      } finally {
        isRefreshing = false
      }
    }
    return Promise.reject(error)
  }
)
```

### 2.4 API 限流保护

**设计目的：** 防止接口被恶意调用（如暴力破解登录、DDoS 攻击）。

**实现方式：** 基于 Redis + 自定义注解的滑动窗口限流。

**限流注解使用：**

```java
// 登录接口：每个 IP 每分钟最多 5 次
@PostMapping("/login")
@RateLimiter(time = 60, count = 5, limitType = RateLimiter.LimitType.IP,
             message = "登录尝试次数过多，请1分钟后再试")
public Result<?> login(@RequestBody LoginRequest request) { ... }

// Token 刷新：每个 IP 每分钟最多 10 次
@PostMapping("/refresh-token")
@RateLimiter(time = 60, count = 10, limitType = RateLimiter.LimitType.IP,
             message = "令牌刷新次数过多，请1分钟后再试")
public Result<TokenRefreshResponse> refreshToken(@RequestBody TokenRefreshRequest request) { ... }

// 用户操作：每个用户每分钟最多 50 次
@PostMapping("/products")
@RateLimiter(time = 60, count = 50, limitType = RateLimiter.LimitType.USER)
public Result<Product> createProduct(@RequestBody Product product) { ... }
```

**限流切面实现：**

```java
@Aspect
@Component
public class RateLimiterAspect {
    
    private final RedisTemplate<String, Object> redisTemplate;
    
    @Before("@annotation(rateLimiter)")
    public void doBefore(JoinPoint joinPoint, RateLimiter rateLimiter) {
        String key = buildKey(joinPoint, rateLimiter);  // 如 "AuthController:login:192.168.1.1"
        String redisKey = "rate_limit:" + key;
        
        Long currentCount = redisTemplate.opsForValue().increment(redisKey);
        
        if (currentCount == 1) {
            redisTemplate.expire(redisKey, rateLimiter.time(), TimeUnit.SECONDS);
        }
        
        if (currentCount > rateLimiter.count()) {
            throw new RateLimitException(rateLimiter.message());
        }
    }
}
```

**限流策略类型：**

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| `DEFAULT` | 全局限流，所有请求共享配额 | 一般接口 |
| `IP` | 按 IP 地址限流 | 登录、注册等敏感接口 |
| `USER` | 按用户 ID 限流 | 需登录的操作接口 |

```java
private String buildDingTalkUrl(String webhook, String secret) {
    long timestamp = System.currentTimeMillis();
    String stringToSign = timestamp + "\n" + secret;
    
    Mac mac = Mac.getInstance("HmacSHA256");
    mac.init(new SecretKeySpec(secret.getBytes(UTF_8), "HmacSHA256"));
    byte[] signData = mac.doFinal(stringToSign.getBytes(UTF_8));
    String sign = URLEncoder.encode(Base64.getEncoder().encodeToString(signData), UTF_8);
    
    return webhook + "&timestamp=" + timestamp + "&sign=" + sign;
}
```

**核心映射关系：** Java 对象 ←→ 数据库表

```

@Id                            →  id BIGINT PRIMARY KEY

@ManyToOne @JoinColumn         →  category_id BIGINT (外键)
```

```java
    // 通过 JpaSpecificationExecutor<T> 接口，在 Service 层动态拼接查询条件
```

**乐观锁机制 — `@Version`：**

```java
@Entity
public class Product {
    @Version
    private Long version;  // Hibernate 自动维护
}

// 更新时: UPDATE product SET name=?, version=2 WHERE id=? AND version=1
// 如果 version 不匹配 (已被其他人修改), 更新行数为 0 → 抛出 OptimisticLockException
```

**N+1 查询问题与防范：**

```
问题场景: 查询 100 个 Product, 每个 Product 都访问 category 字段
  → 1 次查询 Product + 100 次查询 Category = 101 次 SQL (N+1)

当前状态: 项目仅 2 个 @ManyToOne (Product→Category, Price→Product), 均为 LAZY
  → 懒加载本身不触发 N+1, 但 open-in-view=true 会在序列化时触发

防范措施:
  1. 设置 open-in-view=false (避免隐藏的额外查询)
  2. 使用 @EntityGraph 或 JOIN FETCH 明确加载关联数据
  3. 使用 DTO 投影只查询需要的字段
```

### 2.8 Redis — 缓存层（支持懒加载与自动降级）

**设计理念：** 系统优先尝试使用 Redis，如果 Redis 不可用则自动降级为内存缓存，确保应用始终可用。

```java
@Configuration
@EnableCaching
public class RedisConfig {
    
    // 默认过期时间：基础时间的 80%-120% 随机
    private long getRandomTtl(long baseTtl) {
        double randomFactor = 0.8 + ThreadLocalRandom.current().nextDouble() * 0.4;
        return (long) (baseTtl * randomFactor);
    }
    
    @Bean
    public RedisCacheManager cacheManager(RedisConnectionFactory factory) {
        // 不同缓存类型差异化过期策略
        Map<String, RedisCacheConfiguration> configs = new HashMap<>();
        
        // 产品缓存：30分钟随机过期
        configs.put("products", config.entryTtl(Duration.ofSeconds(getRandomTtl(1800))));
        
        // 字典缓存：2小时随机过期（变化较少）
        configs.put("dict", config.entryTtl(Duration.ofSeconds(getRandomTtl(7200))));
        
        // 用户缓存：15分钟随机过期
        configs.put("users", config.entryTtl(Duration.ofSeconds(getRandomTtl(900))));
        
        return RedisCacheManager.builder(factory)
            .withInitialCacheConfigurations(configs)
            .build();
    }
}
```

### Docker 网络模式对比

| 网络模式 | 工作原理 | 性能 | 适用场景 |
|---------|---------|------|---------|
| **bridge + 端口映射** | 容器独立网络，通过 `docker-proxy` 转发端口 | 多一层转发，略有损耗 | 多实例部署、需要网络隔离 |
| **host 网络** | 容器直接使用宿主机网络，无需端口映射 | 性能最优，无转发损耗 | 单实例、性能敏感服务 |

**当前项目配置**：

```yaml
# docker-compose.yml
services:
  backend:
    network_mode: host    # ✅ Host 网络：直接监听宿主机 8080，无 docker-proxy
  
  frontend:
    # 默认 bridge 网络
    ports:
      - "80:80"           # 可选端口
      - "32080:32080"     # ✅ Bridge + 端口映射：通过 docker-proxy 转发
```

**端口映射原理详解**：

```
┌─────────────────────────────────────────────────────────────┐
│  宿主机 (10.7.5.175)                                         │
│                                                             │
│   ┌─────────────────────────────────────────────────────┐   │
│   │ docker-proxy 进程                                    │   │
│   │ • 监听宿主机端口 32080                                │   │
│   │ • 将流量转发到容器内端口 32080                        │   │
│   │ • 自动跟踪容器 IP（容器重启后 IP 变化也能正确转发）     │   │
│   └─────────────────────────────────────────────────────┘   │
│                         ↓                                   │
│   ┌─────────────────────────────────────────────────────┐   │
│   │ Nginx 容器 (独立网络命名空间)                         │   │
│   │ • 监听容器内 32080                                    │   │
│   │ • 容器内端口与宿主机端口可相同（网络隔离）             │   │
│   └─────────────────────────────────────────────────────┘   │
│                                                             │
└─────────────────────────────────────────────────────────────┘

为什么需要 docker-proxy？
┌─────────────────────────────────────────────────────────────┐
│  问题：容器有独立的网络命名空间，容器内端口不直接暴露给宿主机  │
│                                                             │
│  解决：docker-proxy 在宿主机监听端口，转发到容器网络          │
│                                                             │
│  优势：                                                     │
│  • 容器 IP 动态变化时自动跟踪                               │
│  • 容器重启后自动重新绑定                                   │
│  • 同一镜像可启动多个实例（不同端口映射）                    │
└─────────────────────────────────────────────────────────────┘
```

### Nginx 配置要点

```nginx
# 统一端口架构：PC端和小程序共用 32080 端口
server {
    listen 32080;
    server_name localhost;

    # 前端静态资源
    root /usr/share/nginx/html;
    index index.html;

    # 安全头
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;

    # Gzip 压缩
    gzip on;
    gzip_types text/css application/javascript application/json;

    # API 代理 — 转发到后端容器
    location ^~ /api/ {
        proxy_pass http://host.docker.internal:8080/api/;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # CORS 配置（小程序需要）
        add_header Access-Control-Allow-Origin * always;
        add_header Access-Control-Allow-Methods "GET, POST, PUT, DELETE, OPTIONS" always;
        add_header Access-Control-Allow-Headers "Authorization, Content-Type" always;
    }

    # SPA 路由支持 — 所有路径回退到 index.html
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 静态资源长缓存 (文件名含 hash)
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2)$ {
        expires 30d;
        add_header Cache-Control "public, immutable";
    }
}
```

## 四、核心技术流程

### 4.1 用户登录完整流程

```
用户输入用户名密码
        ↓
前端 POST /api/auth/login { username, password }
        ↓
AuthController.login()
        ↓
UserRepository.findByUsername(username)
        ↓
BCryptPasswordEncoder.matches(输入密码, 数据库哈希)
        ↓ (验证通过)
JwtUtil.generateToken(userId, username, role)
  → 生成 JWT: Header.Payload.Signature
  → Claims: { sub=username, userId=1, role=ADMIN, exp=24h后 }
        ↓
返回 Result<LoginResponse> { token, userId, username, nickname, role }
        ↓
前端 loginAction():
  → localStorage.setItem('token', token)
  → userStore.token = token
  → userStore.user = { ... }
        ↓
后续请求: Authorization: Bearer eyJhbG...
        ↓
JwtAuthenticationFilter.doFilterInternal():
  → 提取 Token → 解析 Claims → 构建 Authentication
  → SecurityContextHolder.setAuthentication(auth)
        ↓
Controller 正常处理业务
```

### 4.2 数据查询流程（含分页）

```
前端 GET /api/products?page=0&size=10&keyword=铜&sortBy=name&sortDirection=asc
        ↓
ProductController.getProducts(page, size, keyword, ...)
        ↓
ProductService.getProducts():
  → Sort.by(ASC, "name")
  → PageRequest.of(0, 10, sort)
  → productRepository.findBy...(keyword, ..., pageable)
        ↓
Hibernate 生成 SQL:
  SELECT * FROM product
  WHERE name LIKE '%铜%' AND status = 'ACTIVE'
  ORDER BY name ASC
  LIMIT 10 OFFSET 0
        ↓
MySQL 返回 10 条数据
        ↓
Hibernate → List<Product> (Entity)
        ↓
Spring Data → Page<Product> { content, totalPages, totalElements, ... }
        ↓
Result.success("查询成功", page)
        ↓
前端接收: response.data.content → 渲染列表
         response.data.totalPages → 分页组件
```

### 4.3 缓存查询流程

```
前端请求字典数据
        ↓
SysDictService.getActiveCategoryNames()
        ↓
@Cacheable(value="dict", key="'categories'")
  → 检查 Redis: GET dict::categories
  → 缓存命中? → 直接返回 (不查数据库)
  → 缓存未命中 → 查询 MySQL → 存入 Redis (TTL 1小时) → 返回
        ↓
修改字典数据时:
  → @CacheEvict(value="dict", allEntries=true)
  → 删除 Redis 中 dict:: 下所有 Key
  → 下次查询重新从数据库加载
```

## 九、学习路径建议

### 入门路线

1. **理解整体架构** — 本文档 + 系统架构图
2. **跑通项目** — 按照 `IDEA部署指南.md` 本地启动
3. **跟踪一个请求** — 从前端按钮点击 → API 调用 → Controller → Service → Repository → 数据库 → 返回
4. **理解认证流程** — 登录 → JWT 生成 → 请求携带 Token → Filter 验证

### 前端进阶

1. **Vue 3 响应式原理** — `ref` / `reactive` / `computed` 的依赖追踪机制
2. **Composable 设计模式** — 以 `useDict` 为范本，理解状态提取与逻辑复用
3. **Axios 拦截器机制** — 请求拦截 (Token 注入) + 响应拦截 (解包 + 错误处理)
4. **Pinia Store 设计** — 状态 / 计算属性 / 操作 的职责划分

### 后端进阶

1. **Spring Security 过滤器链** — 理解每个 Filter 的职责和执行顺序
2. **JPA 生命周期** — Entity 状态转换 (Transient → Managed → Detached → Removed)
3. **缓存策略** — `@Cacheable` / `@CacheEvict` 的使用场景和 Key 设计
4. **事务管理** — `@Transactional` 的传播行为和隔离级别

### 部署进阶

1. **Docker 多阶段构建** — 理解编译阶段和运行阶段的分离
2. **Nginx 反向代理** — SPA 路由回退 + API 代理 + 静态资源缓存
3. **环境变量管理** — 敏感配置的外部化，`docker-compose.yml` 中的环境变量传递
