# 01. 宏观架构概览

> 先不看代码，**用 5 分钟理解整个系统长什么样**。

---

## 一、系统是什么？

**矿产品价格管理系统**：一个给矿山企业用的内部业务系统，管两件事——

1. **产品**：矿山出产的各种矿产品（铜、铅、锌精粉…），分类、客户、产地、价格
2. **价格**：上述产品的实时报价、历史价格、审批流程、对外发布

谁会用？
- **管理员**（ADMIN）：管用户、菜单、看所有日志
- **编辑员**（EDITOR）：录入价格、走审批
- **查看员**（VIEWER）：只读看数据

## 二、架构大图

整个系统分三大块：

```
┌─────────────────────────────────────────────────────────┐
│                       用户                               │
└──────────────┬───────────────────────────┬───────────────┘
               │ 浏览器                    │ 手机/小程序
               ▼                           ▼
       ┌──────────────┐           ┌────────────────┐
       │  H5 前端     │           │  uni-app 前端  │
       │ Vue3 + Vite  │           │ Vue3 多端      │
       └──────┬───────┘           └────────┬───────┘
              │ HTTP (JSON)                │ HTTP
              ▼                            ▼
       ┌──────────────────────────────────────────┐
       │        Spring Boot 后台（本教材重点）       │
       │  ┌─────────────────────────────────────┐ │
       │  │  Controller（接收请求）              │ │
       │  │  Service（业务逻辑）                 │ │
       │  │  Repository（数据库操作）            │ │
       │  │  Security（鉴权 / 限流 / 防攻击）    │ │
       │  └─────────────────────────────────────┘ │
       └──────────────┬────────────┬─────────────┘
                      │            │
              ┌───────▼──────┐  ┌──▼──────────┐
              │   MySQL      │  │   Redis     │
              │  业务数据    │  │  缓存/限流   │
              └──────────────┘  └─────────────┘
```

**三个关键词**：

- **前后端分离**：前端只管界面，后端只管数据，两者通过 JSON 通信
- **单体应用**：所有业务功能在一个 Spring Boot 工程里，没用微服务
- **RESTful API**：后端暴露 `/api/xxx` 形式的接口，前端通过 HTTP 调用

## 三、为什么用 Spring Boot？

很多人会问：Java 后台框架有 Spring、SpringMVC、SpringBoot… 这么多，它们啥关系？

```
Spring（春天）       = 一个庞大的"全家桶"工具集（2003 年诞生）
  └─ Spring MVC     = 其中专门处理"网页请求"的部分
  └─ Spring Data    = 其中专门操作"数据库"的部分
  └─ Spring Security = 其中专门处理"登录/权限"的部分
       │
       ▼
Spring Boot（2014 年）= 给 Spring 套了一个"开箱即用"的外壳
                       让你 5 分钟跑起来一个 Web 服务
```

Spring Boot 解决的核心痛点：**配置地狱**。在 Spring 时代，你要写一堆 XML 才能启动项目；Spring Boot 用"约定大于配置"的思想，帮你把 80% 的样板配置都省了。

本项目用的是 **Spring Boot 4.0.6**（截至 2026 年的最新主版本）。

## 四、后端模块怎么划分？

打开 `backend/src/main/java/com/pricemanagement/` 你会看到：

```
com.pricemanagement/
├── PriceManagementApplication.java   ← 启动类（整个程序的入口）
├── controller/    ← 控制器层（接收 HTTP 请求）
├── service/       ← 业务层（处理业务逻辑）
├── repository/    ← 数据访问层（操作数据库）
├── entity/        ← 实体类（对应数据库表）
├── dto/           ← 数据传输对象（接口入参/出参）
├── config/        ← 配置类（Bean、拦截器、过滤器）
│   └── properties/← 配置属性类
├── annotation/    ← 自定义注解（如 @OperationLog）
├── util/          ← 工具类
├── constants/     ← 常量类
├── exception/     ← 自定义异常
└── listener/      ← 事件监听
```

**这就是经典的"分层架构"**，我们将在 [04 分层架构](04-layered-architecture.md) 详细讲每一层的职责。先记住一句话：

> **Controller 管"进门出门"，Service 管"业务逻辑"，Repository 管"读写数据库"。**

## 五、一个请求的旅程

假设前端要**查所有产品列表**，请求会经过这些层：

```
浏览器 → http://localhost:8080/api/products
         │
         ▼
┌─────────────────────────────────────────────┐
│ Spring Security 过滤器链（先验证身份）        │ ← 06 讲
│   - 有没有 Token？Token 是不是有效的？        │
│   - 用户有没有访问这个接口的权限？             │
└─────────────────────────────────────────────┘
         │ 通过
         ▼
┌─────────────────────────────────────────────┐
│ ProductController.list()                    │ ← 04 讲
│   - 接收分页参数 page=1, size=20            │
│   - 调用 service                              │
└─────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────┐
│ ProductService.list(page, size)             │ ← 04 讲
│   - 检查 Redis 缓存里有没有                   │ ← 07 讲
│   - 有 → 直接返回                              │
│   - 没有 → 调 repository 查数据库              │
└─────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────┐
│ ProductRepository.findAll(PageRequest)      │ ← 05 讲
│   - JPA 自动生成 SQL：SELECT * FROM product │
│   - 把结果映射成 List<Product> 对象          │
└─────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────┐
│ Hibernate 执行 SQL → MySQL 返回数据         │
└─────────────────────────────────────────────┘
         │
         ▼ （原路返回，每层可能包装成 DTO）
返回 JSON：[{ "id": 1, "name": "铜精粉", ... }, ...]
```

**一个"查产品"的简单操作，背后经过了 7~8 层组件的协作。** 这就是后台开发的真实样貌——**每一层只做一件事，组合起来就成了一个完整的请求处理流程**。

## 六、本项目的特殊亮点

这套系统比"教科书版"多了不少企业级特性，作为学习样本非常合适：

| 特性 | 学完之后能吹的牛 |
|------|---------|
| JWT 无状态认证 | "我懂前后端分离怎么登录" |
| Flyway 数据库迁移 | "我会用 Git 管理数据库表结构" |
| Redis 懒加载降级 | "我知道缓存挂了怎么办" |
| 自定义 `@OperationLog` 注解 | "我会写 AOP 切面" |
| API Key + 签名验签 | "我懂给第三方调用的接口怎么鉴权" |
| 钉钉/企微告警 | "我会做应用监控" |
| 操作日志 + 审计 | "我知道金融级系统怎么追溯问题" |

## 七、动手试试

打开 `backend/src/main/java/com/pricemanagement/PriceManagementApplication.java`，找到这一行：

```java
SpringApplication.run(PriceManagementApplication.class, args);
```

想象一下：你双击运行这个 Java 类，它会启动一个 Web 服务监听 8080 端口。然后你用浏览器访问 `http://localhost:8080/api/xxx`，就会触发上面那张图里的流程。

**思考题**：
1. 为什么 "Controller" 单独成一层，不能把数据库操作直接写在 Controller 里吗？
2. 为什么 Redis 在最右边、MySQL 在左下，它们能互换位置吗？
3. 你能猜出 "Service" 这一层可能要做哪些 "Controller" 不会做的事？

答案都在后续章节里。
